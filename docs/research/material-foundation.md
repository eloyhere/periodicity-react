# Material Design 3 / Material You 研究报告

> 面向 Periodicity 组件库扩充的 M3 拆解、批判与迁移方案。
> 读者：主代理（组件库 owner）与后续实现子代理。配套阅读：`docs/design-system/CONTRACTS.md`（硬约束）、`docs/research/visual-language.md`（深色/编辑风视觉）、`docs/research/pain-points.md`（现有痛点与对比度实测）、`docs/research/accessibility.md`（a11y 契约）。

## 0. 一页结论（12 条）

1. **M3 的核心资产是"角色（role）+ 状态（state）"两套词表，不是那套紫粉色板。** 颜色按 primary/secondary/tertiary/error + surface/outline 等 50 个角色组织，组件只引用角色，不引用色值；交互按 6 种 state 建模。这两件事可以整体搬进 Periodicity，色值全部换掉。
2. **颜色角色必须手写映射，不能用 tonal palette 生成。** M3 的 `primary40/80`、`surface neutral6` 是为"任意品牌色都能自动派生"设计的；`#c9f36d` 的青柠 + 近黑绿底一旦过 HCT 生成器会掉饱和度、丢掉编辑风。做法：保留 M3 的**角色名**，值为手工挑选的品牌色（§5.5 给出完整表）。
3. **`surface-tint` 已被官方废弃。** token 注释原文：该 token "should no longer be used and its function/usage has been replaced by the tonal surface colors"。也就是说 elevation 的正确做法是**换 surface 层级（surface-container-low → highest）**，不是叠一层带色蒙版。这条与 Periodicity 现有"foreground → component → background"分层天然同构：**层级 = background 的底色差，不是阴影**。
4. **state layer 的数值可以直接抄：hover 0.08 / focus 0.10 / pressed 0.10 / dragged 0.16 / disabled 0.38。** Periodicity 现在是 0.07/0.12/0.10/0.16/0.45，建议 hover 与 pressed 向 M3 靠拢（press 变轻），disabled 保留 0.45 底线（见 §5.1 的冲突裁决）。
5. **focus indicator 有完整几何规格：3px 粗，外置时 offset 2px，内置时 offset -3px。** 直接把 PERIODICITY 的 2px/3px 焦点环升级为"2px 环 + 2px 间距"或"3px 内嵌"二选一，并保持与相邻色 3:1（WCAG 2.4.13）。
6. **类型比例 15 档只在"角色"层面值得吸收，字号字距不要照抄。** M3 的 display 57/64 到 label-small 11/16 是 Roboto 的拉丁字距（body-large 甚至 +0.5px）；中文必须把 tracking 归零并加行高（`[推断]`，见 §2.3）。Periodicity 的衬线标题 + 等宽 eyebrow 是品牌资产，保留。
7. **shape scale 可以直接用：0/4/8/12/16/20/28/32/48/9999。** Periodicity 现有 10/14/22/32 不在任何 scale 上。**采用双轨**：现有 `--radius-*` 不动（避免 9 个组件视觉跳变），新增 `--shape-xs/sm/md/lg/xl/full`（8/12/16/24/28/999）供新组件使用，老组件重构时再迁移（§5.5.4）。
8. **motion token 建议"取值不取哲学"：** 抄 duration 档位与四条 easing，但拒绝 Expressive 的 spring（damping 0.9 / stiffness 700–3800）与 shape morph——生产力工具不适合"按钮按下时圆角回弹"。
9. **M3 组件 anatomy 的词表（container / label text / leading icon / supporting text / active indicator / handle / track）比它的组件实现更值钱。** 采用这套命名后，二十多个组件的 props 与 CSS 类名可以一次对齐，避免每个组件重新发明命名。
10. **M3 的已知硬伤集中在三处：对比度（官方仓库有 filled tonal button / segmented control 的 WCAG 失败 issue）、暗色主题实现不完整（dark theme 不生效 issue）、Web 实现成熟度（1.0 路线图 issue 75 条评论）。** 这三点正好是 Periodicity 必须自己兜住的地方（§4.2）。
11. **Expressive（2025）的方向是"更大、更圆、更有物理感"，伴随大量弃用：** small FAB 弃用、navigation drawer 被 expanded navigation rail 取代、`surface-tint` 弃用。对 Periodicity 的净收益只有两条：**尺寸阶梯**与**按下反馈**；其余（wavy progress、shape morph、FAB menu）不建议跟进。
12. **最该补的 20 个能力里，P0 的 9 个全是"基础设施 + 高频输入/浮层"**：StateLayer/state token、List、Field+TextInput、Chip、Checkbox、Radio、IconButton、Menu/Popover、Tooltip。它们同时解决现有 pain-points 里的"没有状态契约"与"没有浮层层级"两个结构性问题（§6）。

## 2. M3 架构拆解

### 2.1 token 三层：ref → sys → comp

M3 的 token 是严格三层，层间只允许单向引用 `[A]`：

```
md.ref.palette.*       原始色板（primary40 / neutral6 / error80 …），239 个变量
      ↓
md.ref.typeface.*      Roboto + 字重 400/500/700
      ↓
md.sys.color.*         角色（primary / on-primary / surface-container-high …），50 个
md.sys.typescale.*     15 档（+ emphasized 变体）
md.sys.shape.*         圆角
md.sys.state.*         状态层透明度
md.sys.motion.*        时长/曲线/弹簧
md.sys.elevation.*     0–5 级
      ↓
md.comp.<component>.<element>.<property>   组件 token（177 个文件）
```

对本项目的直接含义：

- **组件只准引用 sys 层**，这是 M3 能在不动组件代码的情况下换主题（含 dynamic color、对比度三档）的唯一原因。Periodicity 目前组件直接引用 `--accent`/`--panel`，等价于"组件引用 ref 层"，换主题必然漏水（`pain-points.md` §1.3 已指出 token 没有分层）。
- 组件 token 的数量是"重"的来源：单是 button 一个组件，官方就有 `_md-comp-filled-button.scss`、`_md-comp-outlined-button.scss`、`_md-comp-text-button.scss`、`_md-comp-filled-tonal-button.scss`、`_md-comp-elevated-button.scss`、`_md-comp-button.scss` + 5 个尺寸文件。**Periodicity 不应复制这个粒度**，只需要 `--button-*` 十来个变量（§5.5）。

### 2.2 颜色角色体系

#### 2.2.1 角色清单（dark scheme，50 个）

`[A]` 实测 dark scheme 的颜色变量共 **50 个**，可归为 6 组：

| 组             | 角色                                                                                                                                                                                                                                                      |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Primary        | `primary` `on-primary` `primary-container` `on-primary-container` `inverse-primary` `primary-fixed` `primary-fixed-dim` `on-primary-fixed` `on-primary-fixed-variant`                                                                                     |
| Secondary      | `secondary` `on-secondary` `secondary-container` `on-secondary-container` `secondary-fixed` `secondary-fixed-dim` `on-secondary-fixed` `on-secondary-fixed-variant`                                                                                       |
| Tertiary       | `tertiary` `on-tertiary` `tertiary-container` `on-tertiary-container` `tertiary-fixed` `tertiary-fixed-dim` `on-tertiary-fixed` `on-tertiary-fixed-variant`                                                                                               |
| Error          | `error` `on-error` `error-container` `on-error-container`                                                                                                                                                                                                 |
| Surface / 中性 | `surface` `surface-dim` `surface-bright` `surface-container-lowest/low/·/high/highest` `on-surface` `on-surface-variant` `surface-variant` `surface-tint`(deprecated) `inverse-surface` `inverse-on-surface` `outline` `outline-variant` `scrim` `shadow` |
| Add-on / 兼容  | `background` `on-background`（**legacy**，注释明说推荐用 surface 替代）                                                                                                                                                                                   |

**要点：** M3 的"层级"不是 `elevation-1/2/3`，而是 `surface-container-lowest → low → (default) → high → highest` 五档 + `surface-dim/bright` 两个极端。这是 2023 年后 tonal surface 改造的结果，也是本项目最该抄的一条。

#### 2.2.2 tonal palette 的真实结构

`[A]` ref palette 239 个变量，并非"每个色相 13 档"这么整齐：

- `primary/secondary/tertiary/error`：0–100，步长 10（11 档常用 + 0/100）。
- `neutral`：**24 档，含 4/6/12/17/22/24/87/92/94/95/96/98/99 等中间调**——这些非 10 倍数的档位正是 surface container 阶梯的来源（`surface` = neutral6，`surface-container` = neutral12，`high` = neutral17，`highest` = neutral22）。
- `neutral-variant`：14 档，供 `outline`(60) / `outline-variant`(30) / `on-surface-variant`(80) 使用。

#### 2.2.3 角色 → 色调（tone）映射（可直接查表）

`[A]` 从 `_md-sys-color.scss` / `_md-sys-color__dark.scss` 提取的关键映射：

| 角色                        | Light             | Dark              | 语义                  |
| --------------------------- | ----------------- | ----------------- | --------------------- |
| `primary`                   | primary40         | primary80         | 主行动色              |
| `on-primary`                | primary100        | primary20         | 主色上的文字/图标     |
| `primary-container`         | primary90         | primary30         | 主色容器（柔和强调）  |
| `on-primary-container`      | primary10         | primary90         | 容器上文字            |

| `surface`                   | neutral98         | neutral6          | 页面/卡片底           |
| `surface-container-lowest`  | neutral100        | neutral4          | 最低层                |
| `surface-container-low`     | neutral96         | neutral10         | 低层                  |
| `surface-container`         | neutral94         | neutral12         | 默认容器              |

这条映射解释了 M3 暗色为什么"越上层的面越亮"：dark 下 surface 是 neutral6，container-highest 是 neutral22，**用明度差代替阴影**。

#### 2.2.4 dynamic color 与对比度三档

- **dynamic color（Material You）**：从壁纸取源色 → HCT 空间 → 生成 5 组 tonal palette → 映射到角色。官方算法在 Material Color Utilities（`[B]` <https://github.com/material-foundation/material-color-utilities>），概念说明见官方 color terms 文档。它的目标是"任意源色都能得到可读的配色"，代价是**源色的辨识度被系统性削弱**（见 §4.2 的社区批评）。
- **对比度三档**：`[A]` 包内同时存在 `_md-sys-color.scss`、`_md-sys-color__medium-contrast.scss`、`_md-sys-color__high-contrast.scss` 及对应 dark 版本，即同一套角色有 standard/medium/high 三份值。**这是 M3 最被低估的设计**：无障碍不是"加个高对比主题"，而是同一角色词表的三套取值。
    - 对 Periodicity 的启示：`visual-language.md` §3.5 已经提出 `data-contrast="high"`，与此完全同构，应正式化为"角色 × 对比度"的二维 token 表，而不是零散覆盖。

### 2.3 类型比例（15 档 + emphasized）

#### 2.3.1 15 档实测值

`[A]` 来源：`_md-sys-typescale.scss`（rem 已换算为 px，root 16px；tracking 为每字号绝对值）：

| 类别     | 档位   | size/line-height | weight | tracking | 字体族 |
| -------- | ------ | ---------------- | ------ | -------- | ------ |
| Display  | large  | 57 / 64          | 400    | -0.25    | brand  |
| Display  | medium | 45 / 52          | 400    | 0        | brand  |
| Display  | small  | 36 / 44          | 400    | 0        | brand  |
| Headline | large  | 32 / 40          | 400    | 0        | brand  |
| Headline | medium | 28 / 36          | 400    | 0        | brand  |
| Headline | small  | 24 / 32          | 400    | 0        | brand  |
| Title    | large  | 22 / 28          | 400    | 0        | brand  |
| Title    | medium | 16 / 24          | 500    | 0.15     | plain  |
| Title    | small  | 14 / 20          | 500    | 0.1      | plain  |
| Body     | large  | 16 / 24          | 400    | 0.5      | plain  |
| Body     | medium | 14 / 20          | 400    | 0.25     | plain  |
| Body     | small  | 12 / 16          | 400    | 0.4      | plain  |
| Label    | large  | 14 / 20          | 500    | 0.1      | plain  |
| Label    | medium | 12 / 16          | 500    | 0.5      | plain  |
| Label    | small  | 11 / 16          | 500    | 0.5      | plain  |

补充事实：

- `[A]` 两个字体族都指向 **Roboto**（`$brand: Roboto; $plain: Roboto;`），字重只有 400/500/700 三档。display/headline/title-large 用 brand，其余用 plain。
- `[A]` **emphasized 变体**（Expressive）：字号/行高/tracking 不变，只提字重——display/headline/title-large 提到 500，title-small/label 提到 600（文件里 wght 轴为 600，但 `$weight-bold` 映射为 700，属实现层不一致）。它本质是"同一个类型比例的两档语气"，不是新增 15 档。
- `[A]` label 的 `text-transform` token 已 deprecated（值 `none`）——M3 不再要求 label 全大写。Periodicity 的 mono eyebrow 全大写是品牌选择，与此不冲突。

#### 2.3.2 对 Periodicity 的判断

- **值得吸收的是"角色分工"**：display/headline 给编辑式标题（衬线），title 给卡片/列表标题，body 给正文，label 给按钮与元数据。这套分工与 `visual-language.md` §4.1 的"三个声部"一致。
- **不值得照抄的是字号与字距**：M3 display-large 57px 在桌面仪表盘里过大；`body-large +0.5px` 的字距是 Roboto 的视觉补偿，换 Avenir/系统字体后会让行变散。
- **中文必须重算** `[推断]`：正文字距置 0（或 -0.01em），行高从 1.5 提到 1.6–1.7；全大写 + 0.14em 的 eyebrow 只对拉丁字符成立，中文 eyebrow 应改为「小字 + 字重 600 + 0.08em」或直接用等宽数字。理由：汉字是等宽方块，额外 tracking 会破坏字组节奏；M3 的 tracking 值来自拉丁字形宽度优化。
- 建议映射见 §5.6。

### 2.4 Elevation 与 tonal surface

`[A]` elevation 只有 6 个等级，且**单位是 px（web 端）**：

| token    | 值   | 典型用途（据组件 token 反推）                       |
| -------- | ---- | --------------------------------------------------- |
| `level0` | 0px  | filled/outlined/text button、filled card、list item |
| `level1` | 1px  | elevated card、elevated button hover、drawer(modal) |
| `level2` | 3px  | menu、navigation bar、chip elevated hover           |
| `level3` | 6px  | dialog、FAB、snackbar、search bar、date picker      |
| `level4` | 8px  | FAB hover、card dragged、chip dragged               |
| `level5` | 12px | 极少用（拖拽峰值）                                  |

（`[A]` <https://unpkg.com/@material/web@2.5.0/tokens/versions/latest/sass/_md-sys-elevation.scss>）

关键结论（三条，均可验证）：

1. `[A]` `surface-tint` 的注释是 **"@deprecated This token should no longer be used and its function/usage has been replaced by the tonal surface colors"**。M3 早期"elevation 越高、叠一层 primary 色蒙版越浓"的做法已废弃，改为**直接换 surface-container 档位**。
2. `[A]` 阴影色只有 `shadow: neutral0`（纯黑）。暗色下纯黑阴影叠在近黑底上几乎不可见——这一点 `visual-language.md` §3.4 已经用实测数字证明（`rgba(0,0,0,.30)` 叠 `#0e1411` 只有 **1.04:1**）。
3. `[A]` 组件 token 显示 M3 自己也在"阴影 + 描边 + 底色"三者间摇摆：outlined card 是 `elevation 0 + outline 1px`，filled card 是 `elevation 0 + surface-container-highest`，elevated card 才是 `elevation 1`。**M3 给了三种表达同一层级的手法**，这正好支持 Periodicity 选择"描边 + 内高光"路线。

### 2.5 Shape scale

`[A]` 完整表（`_md-sys-shape.scss`）：

| 名称                  | 值     | 备注                                            |
| --------------------- | ------ | ----------------------------------------------- |
| none                  | 0      | 全宽分割、tab 容器                              |
| extra-small           | 4px    | menu、snackbar、tooltip、text field（outlined） |
| small                 | 8px    | chip、button pressed 形变目标                   |
| medium                | 12px   | card、button（square 变体）                     |
| large                 | 16px   | FAB、navigation drawer 端部                     |
| large-increased       | 20px   | Expressive 新增                                 |
| extra-large           | 28px   | dialog、bottom sheet（顶角）、date picker       |
| extra-large-increased | 32px   | Expressive 新增                                 |
| extra-extra-large     | 48px   | Expressive 新增（超大容器）                     |
| full                  | 9999px | button、badge、switch、slider、search bar       |

派生形态：`extra-small-top: 4px 4px 0 0`（filled text field）、`extra-large-top: 28px 28px 0 0`（bottom sheet）、`large-start: 16px 0 0 16px`、`large-end: 0 16px 16px 0`（drawer）。**这些"单边/顶角"形态比数值本身更有用**，Periodicity 目前没有对应 token。

Expressive 的 shape morph：`[A]` 在 `_md-comp-button.scss` 里能直接看到实现——按钮默认 `corner-full`，`pressed-container-shape: corner-small`（8px），并配 `pressed-container-corner-size-motion-spring-damping/stiffness`（用 `spring-fast-spatial`）。即"按下瞬间圆角从胶囊变方，用弹簧过渡"。概念页：<https://m3.material.io/styles/shape/shape-morph>。

### 2.6 State layer 与 interaction states

#### 2.6.1 六种状态

`[B]` 官方把交互状态定义为 enabled / hovered / focused / pressed / dragged / disabled（<https://m3.material.io/foundations/interaction/states/overview>），组件 token 里逐状态给出容器色、文字色、图标色、阴影、状态层透明度（`$hover-*`、`$focus-*`、`$pressed-*`、`$dragged-*`、`$disabled-*`）——这是"状态矩阵"最完整的工业实现。

#### 2.6.2 状态层透明度（`[A]` `_md-sys-state.scss`）

| 状态     | 透明度 | 说明                                |
| -------- | ------ | ----------------------------------- |
| disabled | 0.38   | 用于**内容**（文字/图标），容器另算 |
| dragged  | 0.16   | 拖拽                                |
| focus    | 0.10   | 键盘焦点                            |
| hover    | 0.08   | 悬停                                |
| pressed  | 0.10   | 按下                                |

对比度信息：状态层颜色在组件 token 里等于"该容器上的前景色"（如 filled button 的 `hover-state-layer-color: on-primary`），所以它是**用前景色做叠加**，而不是固定黑/白。这点与 Periodicity `Surface` 现在写死的 `rgba(255,255,255,0.26)` ripple 不同（`Surface.css:38`），建议改为 `--state-layer-color: currentColor`。

#### 2.6.3 焦点指示器几何（`[A]` `_md-sys-state-focus-indicator.scss`）

| token        | 值   |
| ------------ | ---- |
| thickness    | 3px  |
| outer-offset | 2px  |
| inner-offset | -3px |

- 外置（按钮、FAB、chip）：3px 环 + 2px 间距。
- 内置（tab、menu item、nav item）：3px 环偏移 -3px（即贴着容器内缘画）。
- `[A]` 焦点环颜色不是 primary，而是 **secondary**（`focus-indicator-color: secondary`），这是为了避免与 primary 填充的选中态混淆。**这是 M3 一个很细但很有用的决策**：Periodicity 现在统一用 accent 作焦点环，在 accent 实心按钮上靠 `--accent-ink` 反色解决（`Button.css:148`），可以借鉴 M3 的"焦点环用第二色"来彻底解耦。

### 2.7 Motion

`[A]` `_md-sys-motion.scss` 全量：

| 组       | token                     | 值                                               |
| -------- | ------------------------- | ------------------------------------------------ |
| Duration | short1/2/3/4              | 50 / 100 / 150 / 200 ms                          |
| Duration | medium1/2/3/4             | 250 / 300 / 350 / 400 ms                         |
| Duration | long1/2/3/4               | 450 / 500 / 550 / 600 ms                         |
| Duration | extra-long1/2/3/4         | 700 / 800 / 900 / 1000 ms                        |
| Easing   | linear                    | cubic-bezier(0, 0, 1, 1)                         |
| Easing   | standard                  | cubic-bezier(0.2, 0, 0, 1)                       |
| Easing   | standard-decelerate       | cubic-bezier(0, 0, 0, 1)                         |
| Easing   | standard-accelerate       | cubic-bezier(0.3, 0, 1, 1)                       |
| Easing   | emphasized                | = standard（token 里直接别名）                   |
| Easing   | emphasized-decelerate     | cubic-bezier(0.05, 0.7, 0.1, 1)                  |
| Easing   | emphasized-accelerate     | cubic-bezier(0.3, 0, 0.8, 0.15)                  |
| Easing   | legacy                    | cubic-bezier(0.4, 0, 0.2, 1)                     |
| Spring   | spatial damping/stiffness | 0.9 / 700（default）、1400（fast）、300（slow）  |
| Spring   | effects damping/stiffness | 1.0 / 1600（default）、3800（fast）、800（slow） |

两个反直觉事实：

- `[A]` 2026 版 token 里 `emphasized` 直接等于 `standard`，真正的"强调"靠 **emphasized-decelerate / accelerate** 两段曲线组合实现（进入用 decelerate，退出用 accelerate）。抄的时候不要只抄 `emphasized` 这个名字。
- `[A]` spring 分 **spatial**（位移/尺寸，允许回弹，damping 0.9）与 **effects**（透明度/颜色，不允许回弹，damping 1.0）两类。M3 自己也不让颜色回弹。

### 2.8 Density

- `[A]` **就这套 web token 包而言，M3 没有全局 density 变量**。密度体现在组件 token 的固定高度上：menu item 48、list item 56/72/88、data table row 52、button 40、text field 56。要"紧凑"只能整组替换组件 token。
- `[B]` M2 曾有显式的 density scale（-3…0，<https://m2.material.io/develop/web/supporting/density>），M3 把它收进了组件配置（Android 的 `VisualDensity`、Compose 的 `minimumInteractiveComponentSize` 48dp）。
- `[推断]` 对桌面生产力应用，正确策略是**定义两档 density（comfortable / compact）并只调 4 个变量**：控件高度、行高、内边距、字号。不要做连续滑杆。

### 3.2 Button：5 个变体 + 5 个尺寸 + 形变

**变体语义（按强调度递减）**：elevated → filled → filled tonal → outlined → text `[B]` <https://m3.material.io/components/buttons/overview>。

- `[A]` filled：容器 `primary`，文字 `on-primary`；hover 加 elevation 1；pressed 回 0。
- `[A]` filled tonal：容器 `secondary-container`，文字 `on-secondary-container`。
- `[A]` outlined：`outline` 1px，文字 `primary`。
- `[A]` text：无容器，文字 `primary`。
- `[A]` Expressive 新增 **5 个尺寸**：xsmall 32 / small 40 / medium 56 / large 96 / xlarge 136；图标 20/20/24/32/40；xlarge 用 headline-large 字号；outlined 的描边在 xlarge 是 3px。
- `[A]` Expressive 的 **toggle 行为**：按钮可有 selected 态，selected 时容器变 `primary`；并且 round/square 两种形状在 selected 与 pressed 时互换（`selected-container-shape-round: medium`、`square: full`）。这就是官方说的"按钮会变形"。
- `[推断]` 对 Periodicity：**只保留 3 个尺寸**（sm 32 / md 42→40 / lg 52），5 个尺寸是为触屏大按钮与 Wear 设计的，桌面用不到 96/136。

### 3.3 Text field：最值得抄的是"状态承载"

- `[A]` filled 的视觉层级：容器 `surface-container-highest` + 底边 1px 激活线；focus 时激活线 2px 且变 `primary`；错误时线变 `error`，label/支持文本同步变 `on-error-container`。
- `[A]` label 两套字号：空态 body-large(16)，填充后 body-small(12)，位置从"输入框内"浮到"边框上/框顶"。这是 M3 最容易被低估的动效，也是中文最容易崩的地方（字重与字号同时变化）。
- `[A]` outlined 的 focus 是 **outline 1px → 3px**（不是加外环），所以它天然满足 WCAG 2.4.13 的"焦点指示面积"要求。
- `[推断]` Periodicity 采用"label 在框外上方 + 常驻"（`TextInput.css` 现状），比 M3 浮动 label 更适合中文与表单密集场景；但应补 `error` / `readOnly` / `counter` / `leadingIcon` / `trailingIcon`，并让支持文本的 id 关联方式与 `accessibility.md` §7 一致。

### 3.4 Chip：四种语义，一个几何

- `[B]` 四种：assist（辅助动作）、filter（筛选，可多选）、input（输入的内容块）、suggestion（建议）。anatomy 见总表。
- `[A]` 高 32、圆角 8、label-large；未选中 filter 有 1px `outline-variant`，选中后 outline 0 且容器 `secondary-container`；hover 时未选中会加 elevation 1（elevated 变体）或不变（flat 变体）。
- `[A]` 选中态的对比度是 M3 的薄弱点：`secondary-container` 上的 `on-secondary-container` 在部分动态配色下不足 4.5:1（见 §4.2 的 issue）。Periodicity 用 `--accent-soft` + `--accent` 文字可达约 **10:1**（§5.5 计算），这是"改造而非照抄"的典型例子。
- `[推断]` 对生产力应用，chip 的真实用途是"筛选器/标签"，建议只做 `filter` 与 `input` 两种语义，assist/suggestion 用 Button 变体替代，减少 API 面积。

### 3.5 Segmented button / Button group / Split button：三者不要混用

- `[B]` segmented button = 单选/多选的**状态控件**；button group = 一组相关动作的**布局容器**（本身不承载选中，Expressive 才有 selected）；split button = 主操作 + 次级菜单。
- `[A]` segmented 高 40、圆角 full、组内 1px 分隔、选中显示 checkmark；button group 高 56（medium）、间距 2、内圆角在按下时从 8 变 4；split 的主按钮左右 padding 24，次按钮 icon 26。
- `[推断]` Periodicity 现在用 `Select` 做"日/周/月"切换，语义错位（下拉 vs 分段）。segmented button 是明确缺口，但排在 P1：它的状态机成本高于 Tabs，先做 Tabs 更划算（§6）。

### 3.6 Switch / Checkbox / Radio：三个尺寸与一个目标

- `[A]` switch：track 52×32、handle 16→24、按下 28、state layer 40、track outline 2px、handle elevation 1。**注意 handle 尺寸随状态变化**，这是 M3 的"物理感"来源，也是最容易在 CSS 里做错的地方（用 `width/height` 过渡即可，不要用 `transform: scale`，否则描边会糊）。
- `[A]` checkbox：18×18、圆角 2、未选中 outline 2px、state layer 40。**M3 的 checkbox 比 Material 2 小了 2px**，视觉更轻，但 18px 在桌面上偏小，需靠 40px 命中区兜底。
- `[A]` radio：icon 20、state layer 40、必须成组。
- `[B]` 三者的语义边界：switch = 立即生效的设置；checkbox = 可多选/可提交；radio = 互斥且通常随表单提交。**不要用 switch 表达"提交后才生效"的选项。**
- a11y 要点：switch 用 `role="switch"`（APG <https://www.w3.org/WAI/ARIA/apg/patterns/switch/>）；checkbox 用原生 input + `indeterminate` 属性；radio 用 `radiogroup` 且方向键切换。

### 3.7 Slider 与 Progress：Expressive 改动最大的两个组件

- `[A]` slider（2026 token）：track 高 **16px**（早期 M3 是 4px），handle **4×44** 的竖条（不是圆点），state layer 40，stop indicator 4，value indicator 高 28 且用 label-medium。Expressive 增加 small/medium/large/xlarge 四种尺度、方向、inset icon。
- `[A]` progress：linear 高 4（thick 8、wave 10/14）、circular 40×40（thick 52、wave 48）、stroke 4、stop indicator 4。**wavy（波浪）是 Expressive 标志性视觉**，用 `$active-indicator-wave-amplitude/wavelength` 控制。
- `[推断]` Periodicity 的 `ProgressRing` 是 132px 的大环 + 中心文字，本质是"数据可视化"而非 M3 的 40px 进度指示器。**不要把 ProgressRing 改成 M3 circular progress**；应该新增一个 16/20px 的 `Spinner` 与 4px 的 `LinearProgress` 供加载态使用。
- a11y：slider 的方向键步长必须与 step 一致，`aria-valuetext` 用于非纯数字（如"中"）；progress 的不确定态不要每帧更新 `aria-valuenow`（会把读屏刷爆）。

### 3.8 Tabs 与 Menu：桌面应用的两条主干

- `[A]` primary tab：高 48（带 icon 64）、指示器 3px、`3px 3px 0 0` 圆角、divider 1px、label title-small；secondary tab 高 48、指示器 2px。tab 的焦点环用 **inner-offset -3px**（画在 tab 内部）。
- `[A]` menu：item 高 48、容器圆角 4、elevation 2、label-large、divider 1px、leading/trailing icon 24。menu 的焦点环同样 inner-offset。
- `[B]` M3 的 tabs 分 primary（同级内容切换）与 secondary（页内次级视图），**与"导航"是两件事**；导航用 navigation bar/rail/drawer。
- `[推断]` Periodicity 的 4 个 nav（Overview/Cycles/Rituals/Insights）是**顶级导航**，不该用 tabs；页面内的"今日/本周/本月"才是 tabs 或 segmented button。当前用 `Select` 做周期切换，属于语义降级。

### 3.9 Dialog / Snackbar / Tooltip / Bottom sheet：浮层的四种"重量"

- `[A]` dialog：圆角 28、elevation 3、headline headline-small(24/32)、body body-medium(14/20)、action label-large；full-screen 变体有独立 token。
- `[A]` snackbar：一行 48 / 两行 68、圆角 4、elevation 3、text body-medium、action label-large。
- `[A]` tooltip：圆角 4、body-small 12/16，无 elevation token（靠反色/描边区分）。
- `[A]` bottom sheet：顶部圆角 28、drag handle 32×4、modal elevation 1；standard 无 scrim，modal 有 scrim。
- `[推断]` 这四者的"重量"应映射为 Periodicity 的 z-index scale（`--z-overlay` / `--z-modal` / `--z-toast` / `--z-tooltip`，`CONTRACTS.md` §4.2 已定义）。**不要给 snackbar 用 dialog 的 elevation**，暗色下两者都是 1px 亮边 + 软阴影，靠层级和位置区分即可。
- a11y：dialog 必须焦点陷阱 + Esc + 归还焦点；snackbar 用 `role="status"` 且不抢焦点；tooltip 不能是唯一信息来源；bottom sheet 的拖拽手势必须有按钮替代（WCAG 2.5.7 Dragging Movements，<https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html>）。

### 3.10 Card / List / Navigation / FAB / Badge：容器类组件

- `[A]` card：圆角 12；elevated 用 elevation 1（hover 2、dragged 4）；filled 用 elevation 0 + `surface-container-highest`；outlined 用 elevation 0 + 1px outline。三者是同一层级的三种表达。
- `[A]` list：item 56/72/88，左右 16，avatar 40，icon 24（Expressive 20），divider 左右缩进 16。**divider 缩进 16 是 M3 的细节**：它让分割线不贴边，视觉上"属于内容"而不是"属于容器"。
- `[A]` navigation bar 高 80、indicator 32×64、icon 24、label-medium；**drawer 宽 360、item indicator 高 56/宽 336**，modal elevation 1。Expressive 把 drawer 标记为 deprecated，推荐 expanded navigation rail（`[B]` <https://m3.material.io/components/navigation-rail/overview>）。
- `[A]` FAB 56×56、圆角 16、elevation 3（hover 4）、icon 24；Expressive 增加 40/56/96 三档并**废弃 small FAB**，新增 FAB menu（替代 speed dial 与堆叠小 FAB）。
- `[A]` badge：小 6×6、大 16、大徽标用 label-small 11/16。
- `[推断]` Periodicity 是桌面优先：**navigation rail（可展开）比 bottom bar 更合适**；drawer 在 ≥960px 时其实是"永久侧栏"，用 M3 的 expanded rail 词表命名（collapsed/expanded）能让响应式行为与官方文档对齐，而不是自创"sidebar"。

### 3.11 Date picker / Search / Data table：三个高成本组件

- `[A]` date picker modal：360×524、header 120、日期格 40×40、year 72×36、圆角 28、elevation 3；docked 变体是 52 高输入框 + 弹出日历。
- `[A]` search bar：高 56、圆角 full、elevation 3、icon 24、avatar 30、leading padding 16；search view 是全屏变体。
- `[A]` data table：header 56、row 52、footer 52、圆角 4、outline 1px；header title-small、cell body-medium；footer 的分页选择器高 36（比普通 text field 矮，是密度差异的实证）。
- `[推断]` 这三个都是 P1/P2，不要先做。Data table 在 Periodicity 的场景里（周期统计）价值高但可用 `<table>` + 现有 token 手工实现，等 List/Tabs 稳定后再抽象。

### 3.12 anatomy 词表（建议直接采用）

M3 的组件 anatomy 命名可以抽出一套**跨组件通用词表**，建议写入 `CONTRACTS.md` 作为新组件的命名规范：

```
container / track / handle / thumb / indicator(active|inactive) / state-layer
label-text / supporting-text / headline / subhead / input-text / placeholder
leading-icon / trailing-icon / avatar / badge / divider / scrim / drag-handle
```

好处：CSS 类名（`.switch__track`、`.slider__handle`）与 props（`leadingIcon`、`supportingText`）一次对齐，不必每个组件重新起名；同时与官方文档可对照，降低评审成本。

## 4. 评价：M3 好在哪，坑在哪

### 4.1 做得好的 7 点（以及为什么被广泛采用）

1. **角色词表是"可讨论的最小单位"。** 设计师说"用 on-surface-variant"而不是"用 #8b9a90"，跨主题、跨对比度、跨平台的讨论才成立。50 个角色覆盖了 90% 的界面语义，且 `on-*` 成对出现，强制实现者思考"这个前景放在哪个背景上"。`[A]` 角色清单见 §2.2.1。
2. **状态被建模成矩阵，而不是零散 hover 样式。** 每个组件 token 都有 `hover/focus/pressed/dragged/disabled` 五组变量（颜色、透明度、阴影、图标色分列）。这是 M3 对工业界最大的贡献：它把"交互反馈"变成了可穷举、可测试的清单。`[A]` 见任一 `_md-comp-*.scss`。
3. **对比度是第一等的产品特性。** 同一套角色有 standard / medium-contrast / high-contrast 三份取值（`_md-sys-color__medium-contrast.scss` 等）。这让"高对比模式"不需要重写组件，只需要换 token 表。`[A]`
4. **每个组件都有官方 anatomy 清单。** 24 个组件、每个 3–10 个命名部件（§3 总表全部来自官方文档），这让"组件评审"有了共同语言：讨论"supporting text 的对比度"而不是"输入框下面那行小字"。`[B]`
5. **无障碍细节被写进规格而非留给实现者。** 48dp 最小触控、3px/2px 焦点环几何、disabled 容器 0.12 与内容 0.38 的**双透明度**、状态不只靠颜色（selected 加 checkmark）、拖拽必须有替代操作——这些在 M3 里是规格的一部分。`[A]` `[B]`
6. **动效系统是"可预算"的。** 4 组时长 × 4 档、四条主曲线、spatial/effects 两类弹簧，且明确颜色不做弹簧。团队可以规定"本项目只用 short4/medium2/long2"，而不是每个组件自选 180ms/200ms/220ms。`[A]`
7. **跨平台一致 + 有研究背书。** Android Views、Compose、Flutter、Web 共享同一套 token 命名，Google 也公开发表了 Expressive 的可用性研究（"Usability Hasn't Peaked: Exploring How Expressive Design Overcomes the Usability Plateau"，ACM，<https://dl.acm.org/doi/10.1145/3772318.3790373>；`[C]` 仅见检索快照，未读到全文）。这类"设计决策有实验数据"的姿态，是它被大团队采用的重要原因。

### 4.2 具体缺陷与争议（逐条给证据）

#### (1) 对比度：官方实现自己就被提了 WCAG issue

`[C]` `material-web` issue **#5759 "Low Contrast in Filled Tonal Buttons and Segmented Controls Affects Accessibility"**（<https://github.com/material-components/material-web/issues/5759>）原文：一位无障碍顾问实测 filled tonal button 与 segmented control 的文字/边框对比度**不满足 WCAG 2.1 的 4.5:1 / 3:1**，并指出"按钮看起来像纯文本，用户无法识别它是可交互的"（报告者以 Material UI 的实现为例，提交在 material-web 仓库；这不影响它作为"tonal 配色对对比度余量不足"的证据）。

这不是孤例，而是 M3 结构性风险：`secondary-container` + `on-secondary-container` 在动态配色下由算法生成，**算法只保证基线方案的对比度，不保证任意源色**。M3 用 `secondary-container` 表达"次强调"，但它的对比度余量本来就比 `primary` 小。

→ 对 Periodicity 的结论：**不要用 `secondary-container` 做按钮/选中态**。改用 `--accent-soft` 底 + `--accent` 文字（按 WCAG 相对亮度公式估算约 **10:1**，见 §5.5.1），这是"品牌色天然高对比"的红利。

#### (2) 暗色主题：官方 Web 实现有实际 bug

`[C]` issue **#5099 "Dark theme not applying on input filled"**（<https://github.com/material-components/material-web/issues/5099>）：使用官方主题工具与 `material-color-utilities` 生成暗色方案后，filled input / select **仍然是亮色**。报告者附了截图，且"未找到 workaround"。

这印证了一个判断：**M3 的暗色不是"把亮色反转"，而是"另一套 role→tone 映射"**，任何一层没接上就会花。Periodicity 的 `[data-theme="light"]` 覆盖式做法（`index.css:45`）在组件变多后会出现同类问题——这也支持 §5.5 的"角色别名层"方案。

#### (3) Web 实现的成熟度与维护状态

`[C]` issue **#3050 "Set up roadmap for v1.0.0 (When is Material Web 3 Coming?)"**（<https://github.com/material-components/material-web/issues/3050>）有 **75 条评论**，本质是社区在追问"Web 版 M3 什么时候可用"。Hacker News 讨论里也出现"Material Web 是不是已经 maintenance mode / 死了"的质疑（`[C]` <https://news.ycombinator.com/item?id=43975352>）。

→ 结论：**不要把 M3 的 Web 实现当依赖**，只抄规格与 token。Periodicity 自研组件库的路线是对的。

#### (4) API / token 的"重"

`[A]` 可量化的重：

- 颜色角色 50 个、ref palette 239 个变量；
- 组件级 token 文件 **177 个**；单 button 就有 5 变体 × 5 尺寸的 token 文件；
- 一个 filled button 的 token 文件里有 **40+ 个变量**（含 5 个状态 × 颜色/透明度/阴影）。

`[推断]` 这种粒度适合"设计系统团队 + 多产品线"，不适合 9 个组件的个人项目。Periodicity 应该用"**少角色、少状态、少尺寸**"的裁剪版：约 18 个颜色角色、5 个状态、3 个尺寸。

#### (5) 视觉辨识度过强 / dynamic color 的同质化

`[C]` Android Authority 的批评文章标题即观点：**"Material You's unicolor themes are doomed to fail"**（<https://www.androidauthority.com/google-material-you-unicolor-themes-3113986/>）。核心论点：从单张壁纸提取的单色相方案会让整个系统变成"同一种颜色的深浅变化"，应用之间失去识别度。

Hacker News 对 Expressive 的高赞吐槽也指向同一处：**"expressive 在这个语境下似乎等于各种柔和的粉紫色调"**（`[C]` 原文 "It looks like 'expressive' in this case means 'various pastel shades of pink and purple'"，<https://news.ycombinator.com/item?id=43975352>）。

→ 对 Periodicity：青柠 + 薄荷/紫/琥珀的**多色相**品牌恰恰是解药，不要为了"符合 M3"把辅助色收拢成主色的深浅。

#### (6) Expressive（2025）的可用性争议

`[C]` HN 讨论（360 points / 149 comments，<https://news.ycombinator.com/item?id=43975352>）里的典型质疑：

- "Animated border radius"——对 shape morph 的第一反应是"花哨"；
- 反讽"把按钮做大就能更快找到"（原文 "Who could have imagined that making a button larger makes it faster to find!"）；
- 对"pastel 化"的审美疲劳（见上条）。

`[B]` 同时，Expressive 带来**大量弃用**：small FAB deprecated、navigation drawer deprecated（改用 expanded navigation rail）、`surface-tint` deprecated。对一个刚起步的组件库，这意味着**跟进 Expressive 的迁移税高于收益**。

→ 结论：吸收尺寸阶梯与按下反馈，**不吸收** shape morph、wavy progress、spring、FAB menu。

#### (7) 动效偏多、偏长，且与 reduced-motion 冲突

`[A]` M3 的时长上限到 **1000ms**（extra-long4），并且提供了弹簧（spatial damping 0.9）。Expressive 的按钮按下会同时改变圆角、阴影、容器色。`[B]` 官方虽然要求尊重 reduced-motion，但**组件级动效组合起来的总时长**在低端设备上会明显拖慢感知。

`[推断]` 对生产力工具：**单次交互的动效预算 ≤ 200ms**，页面级转场 ≤ 300ms，超过 400ms 的动效必须可被"快速模式"关闭。Periodicity 现有的 140/220/320ms 三档是合理的（`CONTRACTS.md` §4.2），不要因为 M3 有 600ms 就放宽。

#### (8) 暗色下 elevation 的物理不可能

`[A]` M3 的阴影色只有纯黑 `neutral0`；`[C]` Periodicity 自己的实测（`visual-language.md` §3.4）：`rgba(0,0,0,.30)` 叠在 `#0e1411` 上对比度只有 **1.04:1**，完全不可见。

M3 的解法是换 surface 层级（§2.4），但代价是**层级越多、底色越亮，暗色越"发灰"**；而且 `surface-container-highest`（neutral22）已经接近中灰，再往上没有空间。这是 M3 暗色在"高层级浮层"上的结构性上限。

→ Periodicity 的"描边 + 内高光"路线在这个点上**优于 M3**，应保留并写进规范（`visual-language.md` §3.5 已有实测表）。

#### (9) 48dp 触控目标 vs 桌面密度

`[B]` M3 的最小触控目标是 48dp（Compose 的 `minimumInteractiveComponentSize`）；`[C]` WCAG 2.2 的 AA 要求是 **24×24 CSS px**（<https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html>），AAA 才要求 44×44。

三个数字（48 / 44 / 24）对应三种场景。Periodicity 现在用 44px（`CONTRACTS.md` §4.2 `--touch-target: 44px`），在桌面端偏大、在触屏端刚好。**建议：视觉尺寸 32–40，命中区 44（桌面）/48（`pointer: coarse`）**，用伪元素扩展而不是撑大视觉。

#### (10) 类型系统的拉丁中心主义

`[推断]`（基于 §2.3 的实测值）：15 档的 tracking 全为拉丁字形优化（body-large +0.5px、label +0.5px），且 label 默认曾要求大写；中文语境下：

- 正文字距应归零，行高应 +0.1；
- 全大写只对拉丁有效，中文 eyebrow 需要另立规则；
- display 档（57/64）对中文标题过大，且衬线中文（宋体/思源宋体）在小字号下笔画会糊。

M3 没有为 CJK 提供专门的类型比例，这是它作为"全球设计系统"的真实缺口。

#### (11) 规范漂移：官网、token、文档三套数

`[A]` 实测例子：slider 的 track 在 2026 token 里是 **16px**，而大众认知（早期 M3）是 4px；button 默认高 40，Expressive 的 medium 是 56；`emphasized` 缓动在 token 里等于 `standard`。`[B]` 官方 Android 文档同时存在"旧组件"与"Expressive 组件"两套说明，且部分组件页直接写"已弃用"。

→ 结论：**以 token 为准，不以博客/截图为准**；并把版本号写进项目文档（本项目锁定 "M3 token v34.0.21 快照"），否则半年后无法解释某个数值从哪来。

### 4.3 一句话结论

M3 值得学的是**词表与状态矩阵**（角色、anatomy、六状态、焦点几何、对比度三档），不值得学的是**生成式配色、Expressive 的物理玩具、以及 48dp 的触屏尺寸假设**。Periodicity 应该做"M3 的语义 + 编辑风的皮肤"。

### 5.2 必须改造的（6 项）

1. **品牌色不能套 tonal palette。** `#c9f36d` 过 HCT 生成器后会被降饱和成"灰绿"，且 `primary40` 在暗色下不可读。做法：角色名保留，值手工指定；`primary` = `--accent`、`on-primary` = `--accent-ink`（实测 14.5:1）。
2. **elevation 用"描边 + 内高光/内发光 + 环境阴影"，不用 M3 的阴影堆叠。** 依据 `visual-language.md` §3.4–3.5 的实测：纯黑阴影在 `#080b09` 上只有 1.04–1.06:1。给出三级 recipe（§5.5.3）；焦点态用 `inset 0 0 0 1px` 亮环 + `inset 0 0 24px` 低透明主色内发光（现有 `TextInput.css` 的 `field__edge` 已是这个做法，应提升为 `--glow-focus` token 复用）。
3. **不要紫粉渐变。** M3 的 dynamic color 会从壁纸/源色生成 pastel 系列；Periodicity 的青柠/薄荷/紫/琥珀是**有意的多色相**，辅助色只用于装饰与分类，不参与交互语义（交互语义只用 primary + error）。
4. **不要 `secondary-container` 做按钮/选中态。** 用 `--accent-soft` + `--accent` 文字（约 10:1），既避开 issue #5759 的对比度坑，也保持品牌。
5. **不要 5 个按钮尺寸。** 保留 sm 32 / md 40 / lg 52 三档（`--control-*` 现在是 32/42/52，建议 md 收到 40 与 M3 对齐；若担心视觉跳动，可保留 42 并把 M3 的 40 记为 `--control-md` 的候选值）。
6. **不要 inverse-surface 的 Snackbar。** M3 的 snackbar 用 `inverse-surface`（亮底），在深色编辑风里会像"一块白板"。改用 `surface-container-highest` + 1px `outline` + 软阴影。

### 5.3 明确拒绝的（7 项）

| 拒绝项                                 | 理由                                                                    |
| -------------------------------------- | ----------------------------------------------------------------------- |
| tonal palette 自动生成 / dynamic color | 削弱品牌辨识度（§4.2-5）；青柠会变灰绿                                  |
| 15 档类型比例全量落地                  | 桌面用不到 57px display；中文 tracking 不适用（§4.2-10）                |
| Expressive shape morph（按下变圆角）   | 与"克制"的编辑风冲突；HN 第一反应是"花哨"（§4.2-6）                     |
| spring 动效（damping 0.9）             | 生产力工具的高频操作会被"果冻感"拖慢；reduced-motion 成本高             |
| wavy progress                          | 装饰性 > 信息性；周期进度已有 ProgressRing                              |
| 5 种按钮尺寸 / 5 种 FAB 尺寸           | 尺寸爆炸；桌面用不到 96/136                                             |
| navigation drawer 的官方弃用结论       | 桌面侧栏是正确形态，只是改用 expanded rail 的词表（collapsed/expanded） |

### 5.4 三层模型落地（含与现有 CONTRACTS 的冲突裁决）

`CONTRACTS.md` §2 把 `.state-layer` 放在 **background** 层，而本次任务书要求"state layer 放 foreground"。两者都能工作，但语义不同，必须裁决，否则子代理会写出两套实现：

| 放置                   | 优点                                                        | 缺点                                                       |
| ---------------------- | ----------------------------------------------------------- | ---------------------------------------------------------- |
| background（现状契约） | 文字不被叠色，正文更锐利；适合大面积容器                    | 状态层在内容之下，pointer 反馈"隔了一层"；与 M3 的观感不同 |
| foreground（任务书）   | 与 M3 一致（状态叠在内容上），按压反馈直接；ripple 天然同层 | 8–10% 的叠色会让文字轻微发灰，长文本可读性下降             |

**裁决（建议写回 `CONTRACTS.md` §2）**：按组件类型分流，一个 prop 控制，默认 `foreground`。

```tsx
type StateLayerPlacement = "foreground" | "background";

// 交互容器（Button / Chip / Tab / ListItem / MenuItem）：foreground
// 大面容器（Card / Dialog / Sheet / Panel）：background
<Surface stateLayer="foreground" stateLayerColor="currentColor" />;
```

**三层职责最终定义：**

| 层                   | 放什么                                                                                                                                      | 禁止                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| **background**（z0） | tonal wash（`color-mix(in oklab, var(--color-primary) 4%, transparent)`）、网格/噪点、渐变、progress 轨道、图片底衬、大面容器的 state layer | 文本、可聚焦元素、事件                      |
| **component**（z1）  | 全部内容与可交互元素、事件绑定、`data-state`                                                                                                | 纯装饰                                      |
| **foreground**（z2） | **state layer（hover/focus/press）**、ripple、focus ring、edge highlight（`inset 0 1px 0 rgba(255,255,255,.06)`）、角标                     | 任何命中测试（必须 `pointer-events: none`） |

**foreground 内部顺序（同一层用 DOM 顺序控制）：**

```
.surface__foreground
├── .surface__state-layer     ← 状态叠色（currentColor × opacity）
├── .surface__ripple          ← 指针波纹（仅 pointerdown 后 ~400ms）
├── .surface__focus-ring      ← 2px 环 + 2px offset（仅 :focus-visible）
└── .surface__edge            ← 静态内高光/描边（永远在最上，避免被叠色污染）
```

CSS 要点（与 `CONTRACTS.md` §1 "禁用 grid" 一致，用 absolute 叠层）：

```css
.surface {
    position: relative;
    isolation: isolate;
}
.surface__background,
.surface__foreground {
    position: absolute;
    inset: 0;
    pointer-events: none;
}
.surface__component {
    position: relative;
    z-index: 1;
}
.surface__foreground {
    z-index: 2;
}
.surface__state-layer {
    position: absolute;
    inset: 0;
    border-radius: inherit;
    background: currentColor;
    opacity: 0;
    transition: opacity var(--duration-fast) var(--ease-standard);
}
.surface[data-state="hover"] .surface__state-layer {
    opacity: var(--state-hover-opacity);
}
.surface[data-state="pressed"] .surface__state-layer {
    opacity: var(--state-press-opacity);
}
.surface[data-state="focus"] .surface__state-layer {
    opacity: var(--state-focus-opacity);
}
```

**注意**：现有 `Surface` 用 `display: grid` 叠三层，与契约 §1 的"禁用 grid"冲突（契约也注明"现有 Surface 由主代理统一改为 flex"）。上面的 absolute 方案正好一并解决。

#### 5.5.1 颜色角色别名层

原则：**老 token 不动，新增 `--color-*` 别名指向老 token**；只有新增角色才给字面量。这样现有 9 个组件零改动，新组件一律用角色名。

亮色主题的映射要点（**方向会翻转**，这是最容易踩的坑）：

| 角色                        | 暗色                    | 亮色                 | 说明               |
| --------------------------- | ----------------------- | -------------------- | ------------------ |
| `surface`                   | `#080b09`（最深）       | `#f3f0e7`            | 页面底             |
| `surface-container-lowest`  | `#050706`               | `#fffdf6`            | 暗色更低、亮色更高 |

| `surface-container-highest` | `#1b2a20`               | `#ece8dc`            | 输入/对话框        |
| `on-surface`                | `#eff5ee`               | `#182019`            | 主文字             |
| `outline`                   | `rgba(231,244,234,.36)` | `rgba(24,32,25,.36)` | 控件边界           |

#### 5.5.3 elevation recipe（3 级，替代 M3 的 0–5）

```css
:root {
    /* L1：卡片/输入框 —— 靠 1px 描边 + 顶边内高光，不加投影 */
    --elevation-1: inset 0 1px 0 rgba(255, 255, 255, 0.06), 0 1px 2px rgba(0, 0, 0, 0.35);
    /* L2：菜单/下拉 —— 描边 + 中等扩散 */
    --elevation-2:
        inset 0 1px 0 rgba(255, 255, 255, 0.07), 0 8px 24px rgba(0, 0, 0, 0.38), 0 2px 6px rgba(0, 0, 0, 0.28);
    /* L3：Dialog/Sheet —— 大扩散 + 1px 亮描边（必须与 --color-outline 同用） */
    --elevation-3:
        inset 0 1px 0 rgba(255, 255, 255, 0.08), 0 24px 64px rgba(0, 0, 0, 0.52), 0 4px 12px rgba(0, 0, 0, 0.32);
}
```

M3 的 0–5 级映射关系：`0 → 无`、`1 → --elevation-1`、`2/3 → --elevation-2`、`4/5 → --elevation-3`。**保留 M3 的"层级语义"，但压缩为 3 档**，因为暗色下 6dp 与 8dp 的阴影差异不可见（`pain-points.md` §1.2 的实测）。

### 5.7 新组件 props 建议（可直接抄进实现）

```ts
// 1) StateLayer：所有交互组件的状态叠层
export interface StateLayerProps {
    placement?: "foreground" | "background"; // 默认 foreground
    color?: string; // 默认 currentColor
    radius?: string; // 默认 inherit
    disabled?: boolean;
}

// 2) Checkbox / Radio：受控 + 非受控，统一 onCheckedChange
export interface CheckboxProps {
    checked?: boolean;
    defaultChecked?: boolean;
    onCheckedChange?: (checked: boolean) => void;
    indeterminate?: boolean;
    invalid?: boolean;
    disabled?: boolean;
    size?: "sm" | "md";
    label?: ReactNode; // 有 label 时整行可点
}
export interface RadioGroupProps {
    value?: string;
    defaultValue?: string;
    onValueChange?: (value: string) => void;
    orientation?: "horizontal" | "vertical";
    label: string; // radiogroup 的可访问名
    children: ReactNode;
}

// 3) Menu：组合式，焦点管理交给 useRovingTabIndex
export interface MenuRootProps {
    open?: boolean;
    defaultOpen?: boolean;
    onOpenChange?: (open: boolean) => void;
}
export interface MenuItemProps {
    onSelect?: () => void;
    leadingIcon?: IconName;
    trailingText?: string;
    disabled?: boolean;
    destructive?: boolean; // 用 error 角色
}

// 4) Tabs：primary/secondary 两个变体，不承载路由
export interface TabsProps {
    value: string;
    onValueChange: (value: string) => void;
    variant?: "primary" | "secondary"; // 3px / 2px indicator
    children: ReactNode;
}

// 5) SegmentedControl：单选/多选二选一，不暴露布尔爆炸
export interface SegmentedControlProps {
    options: readonly { value: string; label: string; icon?: IconName }[];
    value: string | readonly string[];
    onChange: (value: string | readonly string[]) => void;
    selectionMode?: "single" | "multiple";
    size?: "sm" | "md";
    disabled?: boolean;
}

// 6) Tooltip：延迟 + 键盘可达
export interface TooltipProps {
    content: ReactNode;
    placement?: "top" | "bottom" | "left" | "right";
    delay?: number; // 默认 400ms
    children: ReactElement; // 触发器，clone 后挂 aria-describedby
}

// 7) Toast：一条一条排队，不抢焦点
export interface ToastOptions {
    message: string;
    action?: { label: string; onClick: () => void };
    duration?: number; // 默认 5000ms；含 action 时 8000ms
    tone?: "neutral" | "success" | "danger";
}

// 8) Chip / FilterChip
export interface ChipProps {
    children: ReactNode;
    selected?: boolean;
    onSelectedChange?: (selected: boolean) => void;
    leadingIcon?: IconName;
    onRemove?: () => void; // input chip
    disabled?: boolean;
}

// 9) List：接 adapter（CONTRACTS §7 硬要求）
export interface ListProps<T> {
    adapter: ListAdapter<T>;
    renderItem: (entry: ListEntry<T>) => ReactNode;
    selectedKeys?: ReadonlySet<string>;
    onSelectionChange?: (keys: ReadonlySet<string>) => void;
    density?: "comfortable" | "compact";
}
```

统一约定（与 `CONTRACTS.md` §8 一致，新增两条）：

- 所有交互组件必须输出 `data-state="rest|hover|focus|pressed|disabled"`，样式只准选 `data-state`，不准选 `:hover`（便于测试与统一状态层）。
- 所有带 `on*Change` 的组件同时支持受控/非受控，内部用 `useControllableState`。

### 5.8 验收清单（可 lint / 可评审）

1. `Select-String -Path src/component/**/*.css -Pattern "#[0-9a-fA-F]{3,8}"` 只允许出现在 `foundation/tokens.css` 与 `index.css`；组件 CSS 出现字面量色即失败。
2. 每个交互组件必须同时有 `[data-state="hover"]`、`[data-state="focus"]`、`[data-state="pressed"]`、`[data-state="disabled"]` 四条规则。
3. `:focus-visible` 不得被 `outline: none` 单独覆盖（必须有等价的 `box-shadow` 环或 `outline` 替代）。
4. 触控：`min-height: var(--touch-target)` 或伪元素扩展；`@media (pointer: coarse)` 下 ≥ `--touch-target-coarse`。
5. 每个新动画都有 `@media (prefers-reduced-motion: reduce)` 分支；单次动效 ≤ `--duration-slow`（页面转场除外）。
6. 禁用态用"双透明度"（容器 0.12 / 内容 0.38–0.45），不允许整块 `opacity: .4` 一把梭（会让描边一起消失）。
7. 浮层组件必须走 `Portal` + `useFocusTrap`/`useDismiss` + `--z-*`，不允许各自写 `position: fixed; z-index: 9999`。
8. 新组件不得 import 其它业务模块的 CSS；只 import `foundation` 与自己的 CSS（`CONTRACTS.md` §3.1）。

## 6. 组件优先级矩阵

评分口径：**价值 / 成本 / 一致性** 各 1–5 分（成本越高分越高＝越难；一致性越高＝越贴合现有架构）。总分 = `价值 × 2 + 一致性 − 成本`，用于排序，不作为唯一决策依据。

### 6.1 P0（9 项，先做，互为依赖）

| #   | 能力                                    | 价值 | 成本 | 一致性 | 总分 | 为什么是 P0                                                                                          |
| --- | --------------------------------------- | ---- | ---- | ------ | ---- | ---------------------------------------------------------------------------------------------------- |
| 1   | **StateLayer + 状态 token**             | 5    | 2    | 5      | 13   | 所有交互组件的公共底座；一次做完，后面 8 个组件都省事；同时解决 `pain-points.md` §1.3 "没有状态契约" |
| 2   | **List / ListItem（接 adapter）**       | 5    | 3    | 5      | 12   | Rituals/Cycles 列表是核心界面；adapter 契约已定，只差组件                                            |
| 3   | **Field / FieldGroup + TextInput 扩展** | 5    | 3    | 5      | 12   | 现有 TextInput 无 error/readOnly/counter/icon；表单是最高频输入                                      |
| 4   | **Chip / FilterChip**                   | 4    | 2    | 5      | 11   | 筛选是最常见的操作；32px 小控件，成本低                                                              |
| 5   | **Checkbox**                            | 4    | 2    | 5      | 11   | 缺失的基础控件；原生 input 成本极低                                                                  |
| 6   | **Radio / RadioGroup**                  | 4    | 2    | 5      | 11   | 与 Checkbox 同批实现，方向键逻辑复用                                                                 |

## 附录 A：本报告的 6 条"反常识"发现（便于口头传播）

1. M3 的 `surface-tint` 已废弃——"越高越亮"不是审美，是 token 层级的替代方案。
2. `emphasized` 缓动在 token 里等于 `standard`；真正有用的是 `emphasized-decelerate/accelerate`。
3. M3 的 disabled 是**双透明度**（容器 0.12、内容 0.38），不是整块 opacity。
4. slider 的 track 在 2026 token 里已经是 16px，不是记忆中的 4px。
5. 焦点环颜色在组件 token 里是 `secondary`，不是 `primary`。
6. Expressive 同时弃用了 small FAB、navigation drawer、`surface-tint`——跟进它要先付迁移税。
