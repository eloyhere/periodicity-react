## 1. 研究方法与证据等级

### 1.1 标注体系

| 标记     | 含义                                       | 示例来源                                                                                      |
| -------- | ------------------------------------------ | --------------------------------------------------------------------------------------------- |
| `[A]`    | 官方规范 / 一手团队博客 / 标准文档         | W3C WCAG 2.2、NN/g、Linear 官方博客、Vercel Geist 文档、Material 3、Apple HIG、CSSWG 邮件列表 |
| `[B]`    | 社区逆向分析（数值可信、结论需交叉验证）   | `awesome-design-md` 的 `linear.app` / `raycast` DESIGN.md（社区按真实页面提取 token）         |
| `[推断]` | 跨产品归纳 / 工程经验，无单一直接来源      | 本报告作者的判断                                                                              |
| 实测     | 本报告用 sRGB 相对亮度公式自行计算，可复现 | 见附录 A 的计算方法                                                                           |

### 1.2 计算口径

- 对比度：WCAG 2.2 定义 `(L1+0.05)/(L2+0.05)`，sRGB 线性化后取相对亮度 `[A]`（<https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html>）。
- 亮度阶梯：用 CIELAB 的 **L\***（0–100 感知亮度）衡量"两级 surface 差多少才算看得见"。比 hex 差值更可靠，因为深色区间 sRGB 是非线性的。
- 所有对比度/L\* 数值均在 Node 里按上述公式算出，四舍五入到两位小数。

### 1.3 关键判断

深色 UI 的视觉质量，**80% 取决于三件事**：surface 阶梯是否感知均匀、描边是否分层、饱和色是否有预算。其余（玻璃、噪点、渐变）都是最后 20% 的调味，且极易过量。

### 2.2 逐家可迁移手法（以及不该抄的部分）

**Linear**

1. **surface ladder 是唯一层级手段**：5 级、每级 1px 描边；`ΔL*` 只有 2 左右——精细但可辨。`[B]`
2. **官方明确说**：主题用 LCH 生成，"先定 3 个变量：base color / accent / contrast"，98 个变量全部派生；且**探索期直接用黑白 opacity 搭层级**。`[A]`（<https://linear.app/now/how-we-redesigned-the-linear-ui>）
3. **eyebrow 用正字距**（+0.4px）对抗 display 的强负字距，一眼区分"分类标签"与"标题"。`[B]`
4. ⚠️ 不抄：`ink-tertiary #62666d` 对 `#0f1011` 只有 **3.30:1**（实测），不可用于正文；且 Linear 的 canvas 是 `#010102`，比我们更黑，套过来会失去绿调。`[实测]`

**Vercel / Geist**

1. **"Draw each border once"**：分隔线放在容器边框内侧，避免两条 alpha 边叠加出更亮的交点。`[A]`（<https://vercel.com/geist/colors>）
2. **"Keep material shadows translucent"**：投影必须半透明，否则在深色上留下灰色光晕。`[A]`
3. **组件态三色制**：default / hover / active 各一个颜色角色；边框也各有三档。这是最省心的状态 system。`[A]`
4. ⚠️ 不抄：Geist 的 10 个色阶（gray/blue/red/amber/green/teal/purple/pink）对我们太宽——我们会变成"彩虹深色"，见 §8 雷区 14。

**Raycast**

1. **全站零投影**，深度只靠 4 级 surface + 1px hairline。极强的"工程感"。`[B]`
2. **正字距**（body +0.1~0.4px）在深色底上显著改善可读性——深色底白字视觉上会"变瘦"。`[B]` + `[推断]`
3. **键帽（keycap）作为唯一的"伪 3D"装饰**，且是 1px 渐变而非阴影。这是"克制装饰"的范本。`[B]`
4. ⚠️ 不抄：`ash #6a6b6c` 对 `#0d0d0d` = **3.64:1**（实测），其 tier-4 文本不达 AA。

**Arc / Amie**（学习边界，不学手法）

- 玻璃拟态 + 饱和渐变 wash 在"一个视觉焦点"的营销场景成立；在**信息密集的工作界面**会同时破坏对比度与性能。我们的定位是生产力工具，**玻璃只允许出现在浮层（dialog/menu/command palette）与吸顶栏**。`[推断]`

**Things 3 / Cron**

- "无描边、靠留白分层"只在**单列、大留白、低信息密度**下成立。我们有多列仪表盘 + 数据卡，**必须保留描边**。`[推断]`
- 但可迁移：**图标线性权重统一**与**数字 tabular**。`[推断]`

**Stripe / Mercury**

- 表格与数字：**tabular-nums + 右对齐 + 千分位**，是"专业感"的最大来源之一。`[推断]`
- 阴影用"多层柔化"（2–3 层小 alpha）而不是单层大模糊——深色下尤其明显。`[推断]`

**Superhuman / Notion Calendar**

- 键盘优先界面：**焦点态必须比 hover 态更明显**（因为我们有大量键盘用户）。`[推断]`
- 日历网格：线要淡到"几乎看不见但可对齐"——对底色 1.1–1.3:1。`[推断]`

## 3. 深色 UI 的科学与实践

### 3.1 纯黑 vs 近黑：用 L\* 而不是感觉

实测各级 surface 的 CIELAB L\*：

| 系统                 | 最底色    | L\*      | 最高面    | L\*   | 台阶数                                            |
| -------------------- | --------- | -------- | --------- | ----- | ------------------------------------------------- |
| iOS 深色（UIKit）    | `#000000` | 0.00     | `#3a3a3c` | 24.49 | ΔL\* 10.34 / 7.73 / 6.42                          |
| Linear               | `#010102` | 0.29     | `#191a1b` | 9.19  | ΔL\* 4.34 / 2.08 / 1.98 / 0.51                    |
| Raycast              | `#07080a` | 2.17     | `#121212` | 5.46  | ΔL\* 1.46 / 1.35 / 0.48                           |
| **Periodicity 现状** | `#080b09` | **2.81** | `#141f18` | 10.2  | 不连续（panel / panel-strong / panel-muted 混用） |
| **本报告建议**       | `#080b09` | **2.81** | `#1d2824` | 14.99 | ΔL\* **2.92 / 3.25 / 3.19 / 2.82**（平均 3.05）   |

结论：

1. **不要 `#000000`**。理由三条：OLED 纯黑区域与近黑区域的像素响应差异会造成暗部"拖影/发灰"；纯黑上白字 halation 最严重；且 **L\*=0 时没有下一级可以更暗**，凹陷态（well / inset）无处可去。`[推断]` + 交叉印证：Raycast 用 L\*2.17，小米官方 FAQ 也记录了深色滚动时文字"模糊、偏色"的用户报告（<https://www.mi.com/tw/support/faq/details/KA-541580/>）。
2. **区间取 L\* 2–3**。我们现有的 `#080b09`（L\*2.81）已经在这个甜点，**保留**，但把偏绿的中性色统一到一条 hue 线上（见 §9.1）。
3. **台阶用 ΔL\*≈3**。低于 2 需要靠描边"帮忙"（Raycast 的 1.35 就是这种策略）；高于 6 会出现"灰色塑料板"的廉价感（iOS 的 10.34 在深色下非常"块"）。`[推断]`

### 3.2 对比度与眼疲劳

NN/g 对 1980s–2017 年文献的综述结论（`[A]` <https://www.nngroup.com/articles/dark-mode/>）：

- 正常视力人群，**light mode 在视觉敏锐度与校对任务上全面优于 dark mode**，且**字号越小差距越大**——这是"深色 UI 必须放大字号"的直接证据。
- **夜间环境**下 dark mode 表现更差；深色 UI 的"护眼"主要是主观舒适，不是客观绩效。
- 对比极性对**主观疲劳度没有显著差异**——所以"深色更不累"更多是眩光控制与审美，而不是生理优势。

对应的设计推论 `[推断]`：

| 场景                       | 策略                                                                           |
| -------------------------- | ------------------------------------------------------------------------------ |
| 长文阅读（本应用基本没有） | 对比度降到 12–14:1，行高 1.65–1.75                                             |
| 仪表盘扫读（主要场景）     | 对比度保持 14–17:1 给标题/数字，靠**字号与字重**做层次，而不是靠灰             |
| 小字元数据                 | **不许低于 4.5:1，且不许小于 10.5px**。深色 + 小字 + 低对比 = 三重叠加的不可读 |

WCAG 门槛（`[A]`）：正文 4.5:1；≥18.66px 或 ≥14px 粗体 3:1；非文本 UI 边界 3:1。

> 补充：APCA 是 **WCAG 3 的候选算法**，能更好解释"为什么 4.5:1 在近黑背景上依然难读"（深色下 WCAG 比值会高估可读性），但它**不是 WCAG 2.2 的合规依据**，合规仍看 4.5:1；深色大段正文可用 APCA `|Lc| ≥ 75` 做二次校验。本目录 `accessibility.md` 对此有完整展开。

### 3.3 饱和色发光 / 溢色（chromatic aberration）

`#c9f36d` 对 `#080b09` 是 **15.56:1**——它的亮度接近白色。这意味着：

- 大面积使用 = 大面积高亮 → 眩光，尤其是 22–32px 大圆角填充块。`[实测]`
- 高饱和青柠/紫/蓝在深色底上的边缘会出现**色边（chromatic aberration）**，因为眼睛对不同波长聚焦能力不同（纵向色差）；蓝紫最严重。`[推断]` + 光学原理
- OLED 上更明显：高亮像素旁的低亮像素会出现"光晕溢出"。`[推断]`

**预算制规则**（见 §9.5）：

```css
/* 饱和色：面积 ≤ 视口 12%，每屏最多 1 个 glow 元素 */
--glow-accent:
    0 0 0 1px color-mix(in oklab, var(--accent) 30%, transparent),
    0 0 8px color-mix(in oklab, var(--accent) 18%, transparent);
```

### 3.4 Elevation 在深色下为什么不可见

实测：`rgba(0,0,0,.30)` 叠在 `#0e1411` 上得到 `#0a0e0c`，对比度 **1.04:1**——完全不可见。`.40` 也只有 1.06:1。

所以：

- **阴影在本项目里只能承担一件事：把浮层从背景"分离"出来**（dialog / menu / toast），而不是表达层级高低。
- 真阴影必须配合 **1px 亮描边**或**顶边内高光**才有边界。
- "凹陷"（inset well）**不能靠黑色叠层**，只能靠：更暗的底色（L\* −3）+ `inset 0 1px 2px rgba(0,0,0,.5)` + 顶边暗描边。

### 3.5 描边与内高光：深色的"假体积"

实测白色 alpha 叠在 `#080b09` 上：

| alpha   | 实际色    | 对比度     | 用途                    |
| ------- | --------- | ---------- | ----------------------- |
| 6%      | `#171a18` | 1.13:1     | 极淡分隔、表格内线      |
| **8%**  | `#1c1f1d` | **1.19:1** | 卡片默认描边            |
| **12%** | `#262827` | **1.33:1** | 卡片 hover / 输入框默认 |
| **18%** | `#303230` | **1.53:1** | 输入框 hover / 强分隔   |
| 24%     | `#434644` | 2.07:1     | 焦点邻近、选中块边界    |
| 32%     | `#575958` | 2.80:1     | 高对比主题的输入框边界  |
| **36%** | `#616362` | **3.27:1** | **WCAG 3:1 达标线**     |

**这就是深色 UI 最重要的取舍**：WCAG 1.4.11 要求 UI 边界 3:1，即约 36% 白——但那会让整个界面变成"银线网"，彻底破坏克制感。我们的处理：

1. 默认描边停在 1.2–1.5:1（视觉克制）。
2. **可识别性由"填充差 + 描边 + 焦点环"三者合计承担**，输入框默认就有 `ΔL*≥3` 的填充差。
3. 提供 `data-contrast="high"` 高对比主题（描边 32–36%，text-3 → 4.5:1），给需要的用户。参考 Linear 官方就把 `contrast` 做成了主题生成变量 `[A]`。

### 3.6 玻璃拟态与模糊的使用边界

`backdrop-filter` 的代价：合成层 + 每帧重采样，滚动时掉帧；同时把底下的文字变成"噪声"，直接降低前景文字对比度。

| 允许                            | 上限                                        | 理由                   |
| ------------------------------- | ------------------------------------------- | ---------------------- |
| Dialog 遮罩                     | `blur(10px) saturate(.8)` + 深色 scrim ≥76% | 一次性、静态           |
| 吸顶栏 / 侧栏                   | `blur(14px)` + 底 72% 不透明                | 固定区域，不随内容重绘 |
| Menu / popover                  | `blur(16px)`                                | 小面积                 |
| **卡片 / 列表 / 表格**          | **禁止**                                    | 性能 + 对比度双输      |
| **嵌套 blur（blur 里有 blur）** | **禁止**                                    | 半透明叠加不可预测     |
| 超过视口 40% 的模糊面积         | **禁止**                                    | 移动端直接掉到 30fps   |

另有硬性要求：**每个玻璃面必须有 `@supports not (backdrop-filter: ...)` 的实色回退**，且前景文字要在"最坏底色"上验 4.5:1。`[推断]` + Geist "translucent shadow" 同源思路 `[A]`

## 4. 编辑风（editorial）排版在 UI 中的用法

### 4.1 三个声部，各司其职

| 声部                | 字体                                                                           | 职责                                                     | 禁忌                                                         |
| ------------------- | ------------------------------------------------------------------------------ | -------------------------------------------------------- | ------------------------------------------------------------ |
| **Display（衬线）** | `--font-display`：Iowan Old Style / Palatino Linotype / Book Antiqua / Georgia | 标题、卡片标题、对话框标题、空态一句话、大数字的"文案面" | 不用于正文（<17px 衬线在深色下发虚）；不用于按钮；不用于表格 |
| **Body（无衬线）**  | `--font-sans`：Avenir Next / Segoe UI Variable / system-ui                     | 正文、按钮、表单、表格                                   | 不用 700+（会"喊"）；不用全大写                              |
| **Meta（等宽）**    | `--font-mono`：JetBrains Mono / Cascadia Code / Consolas                       | eyebrow、时间戳、ID、数字、键帽                          | **不用于任何句子**；上限 24 个字符                           |

编辑感来自**声部对比**，不是来自装饰。衬线出现率控制在"每屏 1–3 处"——一旦每个标题都是衬线，它就退化成普通字体。`[推断]`

### 4.2 字号阶梯（含 clamp 数值）

> 设计基准：360px（手机）→ 1440px（桌面）。所有 clamp 的 vw 系数按 1440 视口反推，保证桌面落在目标 px。

| Token             | CSS                                 | 实际 px        | line-height | letter-spacing | 字重 | 用途                               |
| ----------------- | ----------------------------------- | -------------- | ----------- | -------------- | ---- | ---------------------------------- |
| `--fs-display-xl` | `clamp(2.35rem, 4.4vw, 3.85rem)`    | 37.6 → 61.6    | `1.02`      | `-0.032em`     | 500  | 首屏 H1（每页最多 1 个）           |
| `--fs-display-l`  | `clamp(1.9rem, 3.2vw, 2.75rem)`     | 30.4 → 44      | `1.06`      | `-0.028em`     | 500  | 区块 H2                            |
| `--fs-display-m`  | `clamp(1.375rem, 2.4vw, 1.8125rem)` | 22 → 29        | `1.12`      | `-0.018em`     | 500  | 卡片标题（对应现状 `card__title`） |
| `--fs-display-s`  | `clamp(1.125rem, 1.7vw, 1.375rem)`  | 18 → 22        | `1.2`       | `-0.012em`     | 500  | 小标题、对话框副标题               |
| `--fs-heading`    | `1.0625rem`                         | 17             | `1.3`       | `-0.008em`     | 600  | 无衬线分节标题                     |
| `--fs-body-l`     | `1.0625rem`                         | 17             | `1.68`      | `0`            | 400  | 导语 / 阅读面板正文（中文首选）    |
| `--fs-body`       | `0.9375rem`                         | 15             | `1.62`      | `0.004em`      | 400  | 默认正文                           |
| `--fs-body-s`     | `0.8125rem`                         | **13（下限）** | `1.55`      | `0.006em`      | 400  | 次要正文、卡片描述                 |
| `--fs-meta`       | `0.75rem`                           | 12             | `1.45`      | `0.02em`       | 500  | 元数据、表格单元格                 |
| `--fs-label`      | `0.6875rem`                         | **11（下限）** | `1.4`       | `0.14em`       | 600  | eyebrow（等宽 + 全大写）           |
| `--fs-num-xl`     | `clamp(2.2rem, 3.4vw, 2.85rem)`     | 35.2 → 45.6    | `1.0`       | `-0.045em`     | 500  | 大数字（等宽 tabular）             |
| `--fs-num`        | `1.25rem`                           | 20             | `1.1`       | `-0.02em`      | 600  | 中数字、统计                       |

**三条硬下限**（当前代码的直接违规点）：

1. 正文 **≥13px**。`App.css` 里 `font-size: 0.8rem / 0.76rem / 0.74rem` 都在 12px 以下，属于"好看但读不动"。`[实测]`
2. 全大写等宽标签 **≥10.5px**。`App.css` 的 **8.5px**（多处）与 9px 必须上调——NN/g 的证据是"字号越小，负对比极性劣势越大" `[A]`。
3. **绝不出现 8px 以下任何文字**（包括装饰性序号）。

### 4.3 字重与字距

- **衬线只用 500**。Georgia/Palatino 没有真正的 600/700，浏览器合成加粗会让笔画糊成一团。禁用 `font-weight: 700` 于 `--font-display`。`[推断]`
- **负字距只在大字号**：≥24px 用 `-0.02 ~ -0.035em`；18–23px 用 `-0.012em`；<18px 用 `0`。负字距是"大字号视觉校正"，小字号用会粘连。
- **正字距只给等宽与全大写**：`0.12–0.18em`。这是 eyebrow 之所以"像标签"的物理原因——大写字母间距本来就该更松。
- **中文不要用负字距**。CJK 字形已在全角框内对齐，负字距会破坏栅格（`-0.01em` 以内可接受）。`[推断]`
- **`font-synthesis: none` 保留**（现有已设），防止浏览器伪造斜体/粗体。

### 4.4 Measure（每行字数）

经典规则：**45–75 字符，66 最优**（Bringhurst, _The Elements of Typographic Style_；LaTeX `memoir` 手册亦引用同一区间）。`[A]`

落地时有个中文陷阱：`ch` 单位量的是数字 `0` 的宽度（约半角），中文全角字约等于 `1em`。所以：

```css
/* 拉丁文/英文为主 */
--measure-latin: 62ch; /* ≈ 45–75 字符区间的中段 */
/* 中英混排 / 中文为主 */
--measure-cjk: 34em; /* ≈ 30–38 个汉字/行，视觉上等价于 60–70 拉丁字符 */
/* 导语、卡片描述 */
--measure-lead: 46ch;
/* 卡片内正文（窄栏）不允许超过 */
--measure-card: 30em;
```

现有 `App.css` 用 `max-width: 46ch`（导语）与 `20ch`（H1）——**20ch 对中文标题过窄**，会强制 4–6 行；建议中文主标题 `max-width: 12em`（约 12 字/行）配合 `text-wrap: balance`。

### 4.5 段落间距与垂直节奏

```css
/* 中文段落：不缩进、段间留白 */
.prose > * + * {
    margin-top: 0.9em;
}
.prose p {
    text-indent: 0;
}
/* 标题的邻近原则：上 2em、下 0.5em（离谁近就属于谁） */
.prose h2 + * {
    margin-top: 0.5em;
}
.prose h2 {
    margin-top: 2em;
}
/* 卡片内：标题与正文 6–8px，正文与操作 16–20px */
```

- 行高：深色底建议比浅色 **+0.05~0.1**（halation 让行间"发虚"）。正文 1.6–1.7，元数据 1.4–1.45，大标题 1.0–1.12。
- 中文行高 ≥1.6；13px 正文配 1.55 已是极限。

### 4.6 小型大写（small caps）与全大写

- **禁止 `font-variant-caps: all-small-caps`**：我们的衬线栈（Iowan/Palatino/Georgia）没有真 small caps，浏览器会合成"缩小的大写"，笔画变细、灰度变浅，在深色底上直接糊掉。`[推断]`
- 需要 small-caps 观感时，用 **mono + uppercase + 0.14em 字距 + 11px** 替代（现有 `card__eyebrow` / `dialog__eyebrow` 已是这个路线，只需把 8.5px 提到 10.5–11px）。
- **全大写只用于 ≤3 个词的标签**。超过 3 词或 24 字符，改用 sentence case——全大写长文本的可读性下降约 10–15%，且显得"喊叫"。`[推断]`

### 4.7 数字与光学对齐

```css
/* 所有数字：等宽数字 + 统一小数位 */
.numeric {
    font-family: var(--font-mono);
    font-variant-numeric: tabular-nums;
    font-feature-settings:
        "tnum" 1,
        "lnum" 1; /* 等宽 + 等高 */
}
/* 表格数字列右对齐，单位列左对齐 */
.table td.num {
    text-align: right;
    font-variant-numeric: tabular-nums;
}
```

- **光学边距**：衬线大标题左侧的 `T`/`A`/`W` 会显得缩进，加 `margin-left: -0.035em` 补偿。
- **图标与文字**：`line-height: 1` 的图标与 15px 正文并排时，视觉中心比几何中心高约 1px，用 `transform: translateY(0.5px)` 或 `margin-top: 1px` 微调；不要用 `align-items: baseline`（SVG 无 baseline）。
- **悬挂标点**：`hanging-punctuation: first` 仅 Safari 支持；退化方案是给 blockquote 加 `text-indent: -0.4em`。

## 5. 形状与动效

### 5.1 圆角阶梯与嵌套规则

保留现有 4 档（品牌连续性：22/32 是"大圆角"识别点），新增 1 档内嵌档：

| Token      | 值      | 用途                                    |
| ---------- | ------- | --------------------------------------- |
| `--r-2xs`  | `6px`   | 内嵌媒体/缩略图/keycap/进度条、图表柱顶 |
| `--r-xs`   | `10px`  | 标签（非 pill）、小图标按钮、代码块     |
| `--r-sm`   | `14px`  | 输入框、Select、紧凑工具栏              |
| `--r-md`   | `22px`  | 卡片、对话框、Sheet、Toast              |
| `--r-lg`   | `32px`  | Hero 卡、全屏面板、大容器               |
| `--r-pill` | `999px` | 按钮、Badge、Switch、Chip               |

**同心公式**（最重要的一条）：

```css
/* 外层 r_md=22px，内边距 16px → 内层 6px，而不是 22px */
--radius-inner: max(var(--r-2xs), calc(var(--radius-outer) - var(--inset)));
```

| 外圆角 | 内边距    | 正确内圆角      | 常见错误                                    |
| ------ | --------- | --------------- | ------------------------------------------- |
| 22     | 16        | **6**           | 也用 22（角"发胖"，同心圆错觉破裂）         |
| 22     | 20        | **6**（地板值） | 用 2（过尖，与外框冲突）                    |
| 32     | 24        | **8**           | 用 32                                       |
| 14     | 12        | **6**（地板值） | 用 0（内外角语言不一致）                    |
| 22     | 0（满铺） | **0**           | 用 22（内层圆角被外层裁切，反而出现"假角"） |

**规则**：

1. 内圆角 = 外 − 内边距，**下限 6px**（媒体块）/ **0px**（满铺分区）。
2. **不要新增第 6 档**。圆角档位超过 5 个，界面立刻"不一致"（见雷区 8）。
3. 同一视图内，**同级元素的圆角必须一致**：所有卡片 22，所有输入 14，所有按钮 pill。
4. 圆角与尺寸的比例：圆角 ≤ 短边的 1/3；22px 圆角要求元素短边 ≥66px，所以 Badge 不能上 22（用 pill 或 10）。

### 5.2 超级椭圆（squircle）

- iOS 的"连续圆角"本质是 superellipse（n≈5）+ 角部平滑（Figma 的 `corner smoothing`，iOS 约 60%）。`[A]`（<https://www.figma.com/blog/desperately-seeking-squircles/>）
- CSS 侧：`corner-shape: superellipse()` 目前在 **css-borders-4 草案讨论阶段**（CSSWG issue #10653 / #10993），Chromium 仅实验性支持，Safari/Firefox 无。`[A]`（<https://lists.w3.org/Archives/Public/public-css-archive/2025Jan/0131.html>）
- **结论：核心组件一律用普通 `border-radius`**。squircle 只允许用于"品牌标记 / Hero 插画 / 空态图形"，且用内联 SVG mask 实现，必须是 `pointer-events: none` 的纯装饰——因为它的可点击区域与视觉边界不一致，且焦点环无法贴合。`[推断]`

### 5.3 动效 token

| Token             | 值                                | 用在哪                       |
| ----------------- | --------------------------------- | ---------------------------- |
| `--dur-1`         | `80ms`                            | 按下瞬间的颜色变化           |
| `--dur-2`         | `140ms`                           | hover / focus 的颜色、描边   |
| `--dur-3`         | `200ms`                           | 小位移动画、展开、Tab 指示条 |
| `--dur-4`         | `280ms`                           | Dialog / Sheet / Menu 进出场 |
| `--dur-5`         | `420ms`                           | 进度填充、页面级转场（慎用） |
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)`      | 默认（进入+状态）            |
| `--ease-enter`    | `cubic-bezier(0.05, 0.7, 0.1, 1)` | 浮层进场（快出慢停）         |
| `--ease-exit`     | `cubic-bezier(0.3, 0, 0.8, 0.15)` | 浮层退场（慢起快走）         |
| `--ease-linear`   | `linear`                          | 仅循环型进度（spinner）      |

规则：

1. **`ease` / `ease-in-out` 关键字全部淘汰**——它们在小距离位移上显得"黏"。现有 CSS 里共 **37 处**裸 `ease`（实测统计：`App.css` 13、`Select.css` 6、`Button.css` 5、`Switch.css` 4、`TextInput.css` 4、`Dialog.css` 3、`Card.css` 2）需要替换为 token。
2. **退场比进场快**：退场 = 进场的 70%（280 → 200ms）。
3. 只对 `transform` / `opacity` / 颜色 / `box-shadow` 做动画；**绝不对 `width/height/top/left/margin` 做动画**。
4. `prefers-reduced-motion: reduce` 时：所有 transition 压到 1ms（现有做法正确），但 **ripple 应"不渲染"而不是 1ms**（1ms 仍会产生一次全屏闪）。
5. Material 3 的时长区间是 50–1000ms（short/medium/long/extra-long 四组）`[A]`（<https://m3.material.io/styles/motion/easing-and-duration/tokens-specs>）；产品级 UI 应只用 **80–280ms** 这一段，400ms 以上只给"页面级"动作。

### 5.4 状态过渡的"该动什么"

| 交互        | 动的东西                                                                                                   | 时长            |
| ----------- | ---------------------------------------------------------------------------------------------------------- | --------------- |
| hover 按钮  | 背景色 + 描边色（不动位置）                                                                                | 140ms           |
| 按下        | 背景再深一档 + 轻微 `scale(.985)`（仅 solid）                                                              | 80ms            |
| 输入聚焦    | 描边色 + 外环 `box-shadow`                                                                                 | 140ms           |
| Tab 切换    | 指示条 `translateX` + 文字色                                                                               | 200ms           |
| 展开/折叠   | `grid-template-rows` 或 `max-height`（量小）→ 推荐 `height: auto` 的 `interpolate-size` 或直接 `clip-path` | 200ms           |
| Dialog 进出 | `opacity` + `translateY(8px)` + `scale(.99)`                                                               | 进 280 / 出 200 |
| Toast       | `opacity` + `translateY(6px)`                                                                              | 进 200 / 出 160 |

### 5.5 Ripple 的正确与错误用法

现状：`700ms`，`cubic-bezier(0.2, 0.8, 0.3, 1)`，非实心按钮用 `rgba(255,255,255,.26)`。

问题：

- **700ms 太长**。桌面鼠标点击后 0.7 秒还在扩散，会有"黏滞感"。
- **0.26 白在深色底上是一次明显闪光**（对 `#080b09` 约 1.9:1 的瞬时亮度跳变），与"克制"冲突。
- **ghost / quiet 按钮同时有背景色变化 + ripple = 双重反馈**，看起来"脏"。

规范：

| 项             | 规则                                                                                |
| -------------- | ----------------------------------------------------------------------------------- |
| 适用           | 仅 `solid` / `filled` 表面（按钮、可选中的卡片、列表项选中反馈）                    |
| 不适用         | ghost、quiet、outline、menu item、table row、switch、checkbox、icon-only <32px、tab |
| 时长           | **380–420ms**                                                                       |
| 起始透明度     | `0.10–0.14`（白）/ `0.16–0.20`（深色 ink，用于浅色 accent 底）                      |
| 半径           | 到最远角的距离（现有 JS 已实现 `--ripple-size`，保留）                              |
| 缓动           | `cubic-bezier(0.2, 0.8, 0.2, 1)`                                                    |
| 键盘触发       | **不播 ripple**（无 origin，圆心在中心会像"闪一下"）→ 改为 120ms 底色 state layer   |
| reduced-motion | 不渲染 ripple 节点                                                                  |
| 裁剪           | 必须被父级 `border-radius` 裁切（现有 `.surface{overflow:hidden}` 正确）            |

Material 的 state layer 透明度是更省的做法：hover 8% / focus 10% / pressed 10% / drag 16%（on-surface 颜色）。`[A]`（<https://m3.material.io/foundations/interaction/states/state-layers>）建议：**列表/菜单/表格全部用 state layer，只有按钮用 ripple**。`[推断]`

### 5.6 Hover 抬升的克制

现状：`.button--solid:hover` 与 `.button--outline:hover` 都有 `translateY(-1px)`。

- **保留 solid 的 -1px**（这是"可按"的触感），但幅度不得超过 2px。
- **删掉 outline 的位移**：低强调按钮"抬起来"是语义矛盾。
- **列表行/表格行/菜单项永不移位**：密集布局里 1px 位移会造成"整行抖动"的错觉，且 `transform` 不重排但会与滚动惯性打架。
- 位移必须配"回弹为 0"，且不与 `box-shadow` 扩散同时发生（两者叠加会显得"浮"）。
- 触屏设备禁用位移：`@media (hover: hover)` 包裹。

## 6. 数据可视化与装饰

### 6.1 网格背景

现状：`body::before`，72px 网格，`--line`（10% 白，对底色 1.25:1），mask 到 68% 高度。

问题：1.25:1 的网格铺满全屏，在卡片区域会和卡片描边"打架"，产生摩尔纹风险（尤其是 1px 线 + 非整数缩放）。

规范：

```css
.grid-field {
    background-image:
        linear-gradient(var(--border-subtle) 1px, transparent 1px),
        linear-gradient(90deg, var(--border-subtle) 1px, transparent 1px);
    background-size: 72px 72px; /* 72 = 8 的倍数，与间距体系同源 */
    mask-image: linear-gradient(to bottom, #000 0%, transparent 55%);
    opacity: 0.55; /* 有效对比度 ≈1.10:1 */
}
```

- 只出现在**首屏 / 空态 / 页头**，不出现在数据密集区。
- 网格线永远比卡片描边淡一档（1.10:1 vs 1.19:1）。
- **不做网格动画**（缓慢流动的网格是 AI 生成的典型特征）。

### 6.2 噪点

```css
.noise::after {
    content: "";
    position: absolute;
    inset: 0;
    background-image: url("data:image/svg+xml,<svg xmlns='http://www.w3.org/2000/svg'><filter id='n'><feTurbulence type='fractalNoise' baseFrequency='0.8' numOctaves='2'/></filter><rect width='100%' height='100%' filter='url(%23n)' opacity='0.5'/></svg>");
    opacity: 0.025; /* 上限：0.03 */
    mix-blend-mode: soft-light;
    pointer-events: none;
}
```

- 上限 **opacity 0.03**，全站 **1 层**，只在最外层容器。
- 噪点绝不能盖在文字上（会降低文字对比度并引起"脏"感）。
- 噪点必须是静态位图/内联 SVG，不用 GIF/视频。

### 6.3 渐变洗色（wash）

现状：`body` 上 2 个 radial（accent-soft 14% + mint-soft 14%），Card 上 1 个 radial + 1 个 linear，Dialog 上 1 个 radial。

问题：**层级叠加导致不可预测**。卡片的 wash 会落在 body 的 wash 上，两者都是 accent 色 → 局部 accent 浓度翻倍，可能出现"绿色斑块"。

规范：

1. **一屏最多 2 个 wash**，且**只能在 `background` 层级，不能叠加在组件层级**（组件内部禁用新增 wash）。
2. 单个 wash 的 alpha ≤ `0.14`，面积 ≤ 40% 视口。
3. wash 必须绑定语义锚点（Hero、主指标卡），不能"到处撒"。
4. **wash 不能位于正文文本下方**——文字要落在纯 surface 上，否则对比度不可控。

### 6.4 轨道线 / 基线

| 元素                | 颜色                         | 对比度  | 线型                        |
| ------------------- | ---------------------------- | ------- | --------------------------- |
| 图表基线（0 线）    | `--border`（12% 白）         | ≈1.33:1 | 1px solid                   |
| 网格线（水平）      | `--border-subtle`（6–8% 白） | ≈1.13:1 | 1px solid                   |
| 预测/未来区段       | 同上                         | —       | `dashed 2 4`                |
| 轨道（进度环/条底） | `--border-strong`（18%）     | ≈1.53:1 | 1px + `border-radius: pill` |
| 选中/当前刻度       | `--text-3`（7.6:1）          | —       | 1px solid + 2px 端点        |

- **只画水平网格线**，垂直网格留给表格（`<table>` 有自己的 border）。
- 网格线**永远不进入卡片内部**时与卡片描边同色——否则交叉点会更亮（Geist 的 "draw each border once" 就是讲这个）。`[A]`

### 6.5 图表视觉规范

1. 基线（0 线）必须可见，且比网格线强一档。
2. 系列色 ≤3 个：accent（主）、mint（次）、violet（第三）；超过 3 个用中性灰阶而非新色相。
3. 面积图填充 `0.10–0.16` alpha，**禁止 accent→violet 的渐变填充**（AI 感第一特征）。
4. 柱状图顶端圆角 `--r-2xs`（6px），基底方角——传达"从基线生长"。
5. 数据标签用 `--fs-meta`（12px）+ tabular-nums，**不许 10px 以下**。
6. 空数据用虚线基线 + 一句衬线提示，不画"假数据占位"。
7. 禁止：3D、阴影柱、发光点、动态绘制循环、渐变描边。

### 6.6 装饰的"预算制"

| 装饰          | 每屏预算            | 上限参数                 |
| ------------- | ------------------- | ------------------------ |
| wash 渐变     | 2                   | alpha ≤0.14              |
| 噪点          | 1 层                | opacity ≤0.03            |
| 网格          | 1 处（非数据区）    | 对比度 ≤1.12:1           |
| glow（发光）  | **1 处**            | `blur ≤8px`，alpha ≤0.18 |
| 玻璃          | 2 处（浮层 + 吸顶） | blur ≤16px               |
| 插画/SVG 图形 | 1 处/空态           | 线性 1.5px               |

> 超过预算的装饰不是"更高级"，而是"更便宜"。这是本报告最重要的一条审美判断。`[推断]`

## 7. 视觉亮点清单（20 条）

> 格式：**手法** → 为什么好 → 具体数值/CSS → 适用组件

### 7.1 颜色与层级

**① 三级亮度阶梯代替阴影**
为什么好：深色下阴影不可见（实测 1.04:1），亮度阶梯才是唯一可靠的层级语言；且不增加合成层，性能零成本。

```css
--surface-0: #080b09; /* L*2.81  页面 */
--surface-1: #0e1411; /* L*5.73  卡片 */
--surface-2: #141b18; /* L*8.98  卡内嵌套/hover */
--surface-3: #18221e; /* L*12.17 浮层：dialog/menu/toast */
```

适用：Card、Dialog、Menu、Toast、Table 容器、Tabs 面板。

**② 三档描边（而不是一档万能灰）**
为什么好：描边是深色的主要轮廓；一档描边会导致"所有东西一样重"，层级消失。

```css
--border-subtle: rgba(231, 244, 234, 0.08); /* 1.19:1 分隔线/内线 */
--border: rgba(231, 244, 234, 0.12); /* 1.33:1 卡片默认 */
--border-strong: rgba(231, 244, 234, 0.18); /* 1.53:1 输入框/hover */
```

适用：全部容器与表单。

**③ 顶边内高光（"pixel edge"）**
为什么好：1px 的白色内高光模拟"光从上方来"，让扁平色块有极轻微的体积，比阴影便宜且不糊。

```css
box-shadow: inset 0 1px 0 rgba(255, 255, 255, 0.06);
```

适用：Card、Dialog、Button(solid)、Chip、Kbd。

**④ 单一 accent + 三个语义辅色**
为什么好：辅色一旦超过 4 个，界面就变成"彩色便签墙"；语义化辅色（mint=完成/健康、amber=注意、violet=计划/创意、danger=错误）让颜色有**含义**而不只是装饰。

```
accent #c9f36d 15.56:1 ｜ mint #8fe0c8 12.30:1 ｜ violet #b8a6ff 8.94:1 ｜ amber #f0c97d 12.02:1 ｜ danger #ff9a8d 9.23:1（均对 surface-1 实测）
```

适用：Badge、状态点、图表系列、卡片 accent 变体。

**⑤ accent 只做"点"不做"面"**
为什么好：`#c9f36d` 亮度接近白色，大面积会眩光；把 accent 限制在 12% 面积内，它才有"信号"价值。
规则：accent 面积 ≤12% 视口；每屏 ≤1 个 glow；不允许 accent 作为整块卡背景（用 `--accent-soft` 0.10–0.14 的淡洗代替）。
适用：Button(solid/一次一个)、Badge、进度、选中态。

**⑥ 状态层（state layer）代替颜色硬编码**
为什么好：hover/focus/pressed 用"叠加一层半透明 on-surface 色"实现，任何底色下都成立，不用为每个组件算 hover 色。

```css
--state-hover: 0.08;
--state-focus: 0.1;
--state-press: 0.1;
background: color-mix(in oklab, var(--text) calc(var(--state-hover) * 100%), transparent);
```

适用：Menu item、Table row、Tab、Ghost/Quiet 按钮。（M3 state layer 同源 `[A]`）

### 7.2 排版

**⑦ 衬线标题 500 + 负字距**
为什么好：Georgia/Palatino 在 500 权重下笔画最完整；负字距收拢大标题的松散感，形成"编辑刊物"的密度。
`font: 500 clamp(1.375rem,2.4vw,1.8125rem)/1.12 var(--font-display); letter-spacing:-0.018em;`
适用：Card title、Dialog title、EmptyState、H1/H2。

**⑧ 等宽 eyebrow + 0.14em 字距 + 11px**
为什么好：全大写等宽 + 宽字距 = 天然的"分类器"，与衬线标题形成三个声部中最锋利的那一刀。
`font: 600 11px/1.4 var(--font-mono); letter-spacing:.14em; text-transform:uppercase; color:var(--text-3)`
适用：Card eyebrow、Dialog eyebrow、Section label、图表轴标题。

**⑨ tabular-nums + 右对齐数字列**
为什么好：数字跳动会让表格"呼吸"；等宽数字让纵向比较变成可能，这是"专业感"最廉价的来源。
`font-variant-numeric: tabular-nums; font-feature-settings:"tnum" 1; text-align:right;`
适用：Table、ProgressRing 数值、Stat、Calendar。

**⑩ measure 约束（62ch / 34em）**
为什么好：深色长行会"丢行"；45–75 字符是最优区间。`[A]`
`max-width: 62ch`（拉丁）/ `34em`（中文）/ `46ch`（导语）。
适用：Dialog body、EmptyState 描述、Card 描述。

**⑪ 大数字作为视觉锚点**
为什么好：仪表盘需要一个"先看什么"的答案；45px 等宽数字 + 负字距，比任何图标都更快被读到。
`font: 500 clamp(2.2rem,3.4vw,2.85rem)/1 var(--font-mono); letter-spacing:-0.045em;`
适用：Stat card、ProgressRing 中心、Hero metric。

### 7.3 形状

**⑫ 圆角同心（内 = 外 − padding）**
为什么好：同心圆角是"做过设计"与"没做过"的分水岭；错误的内圆角会让角部视觉变胖。
`--radius-inner: max(6px, calc(var(--r-md) - var(--pad)));`
适用：Card 内媒体块、Dialog 内表单块、Menu 内分组、图片缩略图。

**⑬ 5 档圆角 + pill**
为什么好：足够表达"容器 > 输入 > 标签 > 按钮"四级，又不至于乱。超过 6 档必然不一致。
`6 / 10 / 14 / 22 / 32 / 999`
适用：全局。

**⑭ 双层焦点环**
为什么好：accent 环在深色上非常亮，直接贴边会"发光"；先垫一圈背景色（`--bg`）再画 accent，得到干净的"光圈"。

```css
:focus-visible {
    outline: 2px solid var(--accent);
    outline-offset: 2px;
}
/* 或在深色实心组件上： */
box-shadow:
    0 0 0 2px var(--surface-0),
    0 0 0 4px var(--accent);
```

适用：Button、Input、Switch、Tabs、Menu item。

### 7.4 动效

**⑮ 4 档时长 + 2 条曲线**
为什么好：动效"不一致"比"不好看"更致命；把曲线收敛到 2 条（标准 + 进出场）后，整个产品的"手感"统一。
`80 / 140 / 200 / 280ms`，`cubic-bezier(.2,0,0,1)` + `cubic-bezier(.05,.7,.1,1)`。
适用：全局。

**⑯ 颜色过渡短、位移动画长**
为什么好：颜色变化是"即时反馈"，超过 160ms 就"延迟"；位移动画需要时间才"顺"。
hover 140ms / 展开 200ms / 浮层 280ms。
适用：Button、Tabs、Dialog、Menu。

**⑰ Dialog 用 `translateY(8px) + scale(.99)`，不用 `scale(.9)`**
为什么好：0.9 的缩放会让对话框"从远处飞来"，廉价；0.99 只传达"贴近"。
`from { opacity:0; transform: translateY(8px) scale(.99) }`（现有 12px/0.985 已接近，改为 8px/0.99 更克制）
适用：Dialog、Menu、Toast。

### 7.5 装饰与数据

**⑱ 网格只出现在首屏并渐隐**
为什么好：网格是"工程感"的符号，但铺满全屏会变成噪点；渐隐 mask 让它像"图纸的余韵"。
`mask-image: linear-gradient(to bottom, #000, transparent 55%); opacity:.55`
适用：Page header、EmptyState、Hero。

**⑲ 2.5% 噪点**
为什么好：深色大面积纯色会有 banding（色带），2.5% 噪点能打散 banding 且几乎不可见。
`opacity:.025; mix-blend-mode:soft-light;`（仅 1 层，不压文字）
适用：最外层容器 / 大色块。

**⑳ 空态用衬线 + mono 双声部**
为什么好：空态是"品牌语气"最容易被记住的地方；一句衬线短句 + 一行 mono 提示，比插画更高级、更省。
`EmptyState: 衬线 22–29px 一句话 + mono 11px 提示 + 一个 ghost 按钮`
适用：EmptyState、404、加载完成态。

## 8. 视觉雷区清单（18 条）

> 格式：**现象** → 证据 → 我们的禁令

**① 低对比灰字当"高级"**
证据：Linear `ink-tertiary #62666d` 对 `#0f1011` = **3.30:1**；Raycast `ash #6a6b6c` 对 `#0d0d0d` = **3.64:1**（均低于 AA 4.5:1，实测）。我们的 `--faint #5d6b61` 对 `#080b09` = **3.52:1**。
禁令：正文/标签对比度 **≥4.5:1**；`--text-4` 只允许用于 placeholder、disabled 辅助说明、装饰性序号，且必须 ≥4.5:1（`#7e8b81` = 5.55:1）。

**② 8.5px / 9px 的等宽标签**
证据：`src/App.css` 中有 **14 处** `font-size: 8.5px` 或 `9px`（实测统计）。NN/g：字号越小，暗色劣势越大 `[A]`。
禁令：**任何文字 ≥10.5px**；等宽全大写标签 **11px**；正文 ≥13px。

**③ 过度玻璃**
证据：玻璃需要合成层 + 重采样，滚动掉帧；且把背景变成噪声，降低前景对比（见 §3.6）。
禁令：卡片/列表/表格 **禁用** `backdrop-filter`；只允许 dialog scrim、吸顶栏、menu；嵌套 blur 禁止；面积 >40% 视口禁止；必须有实色回退。

**④ 过多发光**
证据：现状同时存在 3 处 glow：Switch 拇指 `0 0 14px rgba(201,243,109,.35)`、ProgressRing `drop-shadow(0 0 6px)`、Field `inset 0 0 28px`。
禁令：**每屏 1 处** glow；半径 ≤8px；alpha ≤0.18；不使用 `inset 0 0 28px` 这种"内部雾光"（它会让输入框看起来"发霉"）。

**⑤ 全大写长文本**
证据：全大写降低词形识别（无 ascender/descender 差异）`[推断]`；且中文没有大小写，全大写只对拉丁有效，混排时非常突兀。
禁令：全大写 **≤3 词且 ≤24 字符**；中文标签**永不** `text-transform: uppercase`。

**⑥ 紫蓝渐变**
证据：2019 年后 AI 生成页面的最显著特征，社区已将其作为"AI slop"的识别标志 `[B]`（<https://github.com/aladicf/better-web-ui/blob/HEAD/skills/frontend-design/reference/ai-slop-detection.md>）。
禁令：**禁止** `violet → blue` / `purple → pink` 渐变；渐变只允许"同色相明度变化"或"accent 到透明"。

**⑦ 玻璃卡片堆叠**
证据：三层玻璃叠在一起时，对比度不可预测（每层都衰减一次）；且视觉上"没有边界"。
禁令：同屏玻璃层数 ≤1（除 scrim 外）；玻璃卡内**不得**再放玻璃。

**⑧ 圆角不一致**
证据：现状硬编码了 `8px`（导航项）、`2px`（图表柱底）、`7px 7px 2px 2px`（柱顶）等游离值，而 token 是 10/14/22/32。
禁令：**除 token 外只允许 `--r-2xs`（6px）与 0**；新硬编码圆角视为 review 阻断项。

**⑨ Hover 位移导致抖动**
证据：列表/表格行 1px 位移在快速扫动时产生"行抖动"错觉；`transform` 虽不重排但会与 sticky 定位冲突。
禁令：列表/表格/菜单 hover **只改背景色与描边**；位移只允许 solid 按钮 `-1px`，且 `@media (hover:hover)` 内。

**⑩ 暗色下的刺眼白块**
证据：`#ffffff` 对 `#080b09` = 21:1，纯白大色块在深色界面里是"手电筒"；纯白 modal / 白色图片底色最典型。
禁令：**禁止纯白填充**；最亮只到 `--surface-4`（L\*15）或 `--text-ink`（文字）；图片容器必须有 `background: var(--surface-2)` + 1px 描边，不允许白底透出。

**⑪ 纯黑背景**
证据：见 §3.1（OLED 拖影、halation、无下沉空间）。
禁令：`#000000` 仅允许出现在遮罩（scrim）与 `color-scheme` 元信息中。

**⑫ 大面积高饱和**
证据：`#c9f36d` = 15.56:1，面积大了就是眩光；紫/蓝在深色上还有色边。
禁令：饱和色面积 ≤12%；不允许整卡 accent 填充；accent 文本只用于 ≤2 词的高亮。

**⑬ 无意义的循环动画**
证据：装饰性 pulsing/rotating/shimmer 会持续占用合成线程并分散注意力（"AI 生成感"二号特征）。
禁令：**循环动画只允许**：Skeleton shimmer、Spinner、进行中状态点；其余一律禁止；且必须 `prefers-reduced-motion` 关闭。

**⑭ 辅色超过 4 个**
证据：Geist 有 8 个色相是因为它服务整个 Vercel 生态 `[A]`；我们的产品只有一个主场景。
禁令：accent + mint + amber + violet + danger = **5 个上限**（danger 不计入"装饰色"）；新增色相需要删除一个旧色相。

**⑮ 用阴影表达层级**
证据：实测黑叠层 1.03–1.06:1，不可见。
禁令：阴影只能用于**浮层分离**（dialog/menu/toast）；卡片禁用 `box-shadow` 表达高低，改用 surface + 描边。

**⑯ 描边 alpha 叠加**
证据：两个 12% 描边相邻会在交点变成 23%（更亮），形成"发光的十字"（Geist 明确点名 `[A]`）。
禁令：分隔线画在容器**边框内侧**（`border-bottom` 而不是额外 `<hr>` + border）；父容器有描边时，子元素不再画外描边。

**⑰ 焦点环被裁切**
证据：全局 `:focus-visible { outline-offset: 3px }` 遇上 `.surface { overflow: hidden }`，靠近容器边缘的可聚焦元素焦点环会被裁掉一半（条件性 bug）。
禁令：`overflow:hidden` 容器内的可聚焦元素用 `box-shadow` 内环（`0 0 0 2px var(--accent) inset`）或容器保留 ≥4px 内边距；`outline-offset` 统一为 2px。

**⑱ 行高过紧 + 中文**
证据：中文没有 x-height 缓冲，13px/1.4 会显得"挤成一条"；深色 halation 进一步压缩可读空间。
禁令：中文正文 line-height **≥1.6**；13px 正文 **≥1.55**；大标题最小 1.0（且必须 ≥32px）。

## 9. 完整 Token 建议

### 9.1 颜色：surface 阶梯

以 "L\* 均匀 + 品牌绿调" 为原则，从 `#080b09`（L\*2.81）向上每级 **+≈3 L\***：

| Token            | 值        | L\*   | 台阶     | 用途                                 |
| ---------------- | --------- | ----- | -------- | ------------------------------------ |
| `--surface-deep` | `#050706` | 1.78  | —        | 凹陷井（inset well）、代码块、遮罩底 |
| `--surface-0`    | `#080b09` | 2.81  | —        | 页面背景（品牌锚点，不改）           |
| `--surface-1`    | `#0e1411` | 5.73  | **2.92** | Card、Panel、Table 容器              |
| `--surface-2`    | `#141b18` | 8.98  | **3.25** | 卡内嵌套块、Input 填充、hover 面     |
| `--surface-3`    | `#18221e` | 12.17 | **3.19** | Dialog、Menu、Toast、Popover         |
| `--surface-4`    | `#1d2824` | 14.99 | **2.82** | Keycap、Chip、Tooltip、最高层        |

> 平均 ΔL\* = 3.05。**低于 2 需要用描边补足可见性（Raycast 策略）；高于 5 会出现"灰塑料板"感。**

### 9.2 颜色：border / text / accent / state


### 9.4 间距阶梯：4 基数还是 8 基数？

**结论：4 作为原子单位，8 作为布局节奏。**

| 方案                | 优点                                                        | 缺点                                                                  | 结论     |
| ------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------- | -------- |
| 纯 8 基数           | 布局整齐、跨屏一致                                          | 图标与文字间距、Chip 内边距只能取 8/16，太粗；22px 圆角无法与间距对齐 | 不够用   |
| 纯 4 基数           | 细腻、可做光学微调                                          | 容易出现 4/12/20 这类"半拍"值，节奏松散                               | 太随意   |
| **4 原子 + 8 节奏** | 组件内用 4/8/12；布局用 16/24/32/48/64；所有值都是 4 的倍数 | 需要 discipline                                                       | **采用** |

```css
:root {
    --space-1: 4px; /* 图标与文字、Badge 内边距 */
    --space-2: 8px; /* 元素间距、Chip 内边距 */
    --space-3: 12px; /* 紧凑组件内边距 */
    --space-4: 16px; /* 卡片内块间距、表单行距 */
    --space-5: 20px; /* 卡片内边距（小屏） */
    --space-6: 24px; /* 卡片内边距（默认）、区块间距 */
    --space-7: 32px; /* 区块间距（大） */
    --space-8: 40px;
    --space-9: 48px; /* 页面级区块 */
    --space-10: 64px;
    --space-11: 80px;
    --space-12: 96px; /* 页级 section */
}
```

## 10. 逐组件视觉规范草案

> 通用约定：所有焦点环 `2px solid var(--accent)` + `outline-offset: 2px`（`overflow:hidden` 容器内改内环）；所有文字对比度 ≥4.5:1；所有动效用 §9.6 token。

### 10.1 Button

| 项          | sm         | md                                | lg                 |
| ----------- | ---------- | --------------------------------- | ------------------ |
| 高度        | 32         | **40**（现状 42，非 4 倍数 → 改） | 48（现状 52 → 改） |
| 水平内边距  | 14         | 18                                | 24                 |
| 字号 / 字重 | 12.5 / 600 | 13.5 / 600                        | 15 / 600           |
| 图标        | 16         | 18                                | 20                 |
| gap         | 6          | 8                                 | 9                  |
| 圆角        | pill       | pill                              | pill               |

- **变体**：`solid`（accent 实心）/ `outline`（1px `--border-strong`）/ `ghost`（透明，hover 上 state layer）/ `quiet`（`--text-3`，hover 上 state layer）。
- **去掉 solid 的 `linear-gradient(135deg, accent-strong, accent)`**：渐变会削弱对比控制，且是"AI 感"的常见来源。改为 `background: var(--accent)` + `inset 0 1px 0 rgba(255,255,255,.26)`。
- **hover**：solid → `background: var(--accent-strong)`；outline → `border-color: var(--border-accent)` + `background: var(--accent-soft)`；**outline 删除 `translateY(-1px)`**（低强调按钮不该"抬起"）。
- **active**：solid `background: color-mix(in oklab, var(--accent) 88%, #000)` + `translateY(0)`；不加 scale。
- **disabled**：`opacity: .45`，`cursor: not-allowed`，无 shadow，无 transform。
- **ripple**：仅 solid/outline 使用；400ms；白 0.12（深色 ink 0.18 on accent 底）。
- **焦点**：`box-shadow: 0 0 0 2px var(--surface-0), 0 0 0 4px var(--accent)`（现有实现正确，把 `--bg` 换成 `--surface-0`）。

### 10.2 Card

- 容器：`background: var(--surface-1)`；`border: 1px solid var(--border)`；`border-radius: var(--r-md)`；`box-shadow: var(--elev-1)`；**删除 `--shadow-sm`**。
- 内边距：`clamp(20px, 3.2vw, 28px)`（现状正确）。
- eyebrow：`11px/1.4 mono 600`，`letter-spacing: .14em`，`--text-3`，全大写 ≤3 词。
- 标题：`--font-display 500 clamp(22px,2.4vw,29px)/1.12`，`-0.018em`，`--text-ink`，`text-wrap: balance`，`max-width: 12em`。
- 描述：`15px/1.62`，`--text-body`，`max-width: var(--measure-card)`。
- wash（仅 accent/mint/violet 变体）：**1 个** radial 于右上，`--wash-alpha`，且只覆盖顶部 40%（不能压正文）。
- hover（可点击卡片）：`border-color: var(--border-strong)`；**不位移、不加重阴影**。
- 焦点（可点击卡片）：内环 `inset 0 0 0 2px var(--accent)`（避免被 `overflow:hidden` 裁切）。

### 10.3 Input / Textarea / Select

- 高度：md 40 / sm 32；内边距 `0 14px`；圆角 `--r-sm`(14)。
- **填充用 `--surface-2`（比卡片亮一档 = "raised field"）**，而不是比卡片更暗——实测更暗的井（1.03:1）不可见。
- 描边：默认 `--border-strong`（1.53:1）；hover 不变色，改 `background: --surface-3`。
- label：`12px/1.35 600`，`--text-3`，**不做 uppercase**（中文无大小写，且全大写 + 0.065em 会让标签比内容更抢眼）；如需拉丁风格，用 `mono 10.5px + 0.12em`。
- placeholder：`--text-4`（5.55:1），**不加 opacity**。
- focus：`border-color: var(--accent)` + `box-shadow: 0 0 0 3px var(--accent-soft)`；**删除 `inset 0 0 28px` 的雾光**。
- error：`border-color: var(--border-danger)` + ring `--danger-soft`；hint `13px --danger`。
- disabled：`--text-4` + `--border-subtle` + `--surface-1`，opacity 不用 0.45（输入框变灰比透明更清楚）。
- 动效：颜色 140ms；不改变高度/位置。

### 10.4 Dialog

- 宽度：sm 420 / md 560 / lg 760；`max-height: min(86vh, 760px)`；圆角 `--r-md`(22)。
- 表面：`--surface-3`；描边 `--border-strong`；`--elev-3`。

- body：`24px 26px`；`15px/1.65 --text-body`；`max-width: var(--measure-cjk)`。

- 关闭按钮：32×32，pill，`--border`，`--text-3`；hover → accent 描边 + `--accent-soft`。
- backdrop：`rgba(3,6,4,.72)` + `blur(10px) saturate(.8)`；**删除 radial 的 accent 光斑**（廉价感来源）；`@supports` 回退到纯 `rgba(3,6,4,.86)`。
- 动效：进 `280ms --ease-enter`，`opacity 0→1`、`translateY(8px)→0`、`scale(.99)→1`；出 `200ms --ease-exit`。backdrop 只做 opacity。

### 10.5 Menu / Popover

- 描边：`1px solid var(--border)`；群组叠放 `-8px` 重叠 + `2px solid var(--surface-0)` 环。
- 状态点：8px，`2px solid var(--surface-1)` 外环，颜色用语义色。
- 禁止：渐变底、随机彩色（除非是"项目色"且来自固定 5 色板）。

### 10.12 Progress（Linear / Ring）

- Linear：高 4 / 6 / 8；轨道 `--border-strong`（1.53:1）或 `--surface-3`；填充 `--accent` 纯色（**无渐变**）+ 顶部 `inset 0 1px 0 rgba(255,255,255,.2)`。
- 不确定态：条宽 35%，`1200ms linear infinite`，**无 glow**。
- Ring：轨道 `--border-strong`；进度 `--accent`；stroke 3/4/6；**删除 `drop-shadow` glow**；中心数字 `--font-mono` + `tabular-nums`，`--fs-num`。
- 数值变化：`stroke-dashoffset` / `scaleX` 用 `420ms --ease-standard`（这是唯一允许 >280ms 的常规动效）。
- 语义：完成度 >100% 时用 mint，不是 accent。

### 10.13 Skeleton

- 形状必须**匹配目标元素**（同高、同圆角），否则加载完成会跳。
- 底色 `--surface-2`；shimmer 用 `linear-gradient(90deg, transparent, rgba(255,255,255,.04), transparent)`，`1400ms ease-in-out infinite`（循环动画是 `ease` 禁令的唯一例外）。
- 圆角：文本行 `--r-2xs`(6) 或直接 pill（高 ≤12px 时）。
- 多个骨架的动画**不要同步**（给每个 `animation-delay` 随机 −0~−1400ms），否则出现"整片闪烁"。
- `prefers-reduced-motion` → 静态色块，不闪。
- 禁止：opacity 脉冲（在深色上产生 banding）。

### 10.14 EmptyState

- 容器：`max-width: 34em`；padding `48px 24px`；居中。
- 图形：96–120px 线性插画，`1.5px` stroke，`--text-4` 单色；**不使用渐变/发光**。
- eyebrow（可选）：`11px mono 600 0.14em --text-3`。
- 标题：`--font-display 500 clamp(22px,2.4vw,29px)/1.12 --text-ink`，一句话 ≤18 字。
- 描述：`15px/1.65 --text-3`，`max-width: 34em`。
- 操作：1 个 `solid` 或 `outline` 按钮 + 可选 1 个文字链接，**不超过 2 个动作**。
- 禁止：插画 + 渐变 + 发光 + 动画同时出现（这就是"AI 空态"的标准配方）。

### 10.15 Icon（视觉规范，`src/component/icon/**` 只读，不由本报告修改）

- **尺寸阶梯**：14 / 16 / 20 / 24；默认 16（正文行内与按钮），20（工具栏/导航），24（独立操作）。
- **线性权重**：16/20px 用 `stroke-width: 1.5`；24px 用 `1.75`；**永远不要 2**（深色底上会显粗、发毛）。`[推断]`
- **颜色**：一律 `currentColor`，不写死色值；默认继承 `--text-3`，hover 升到 `--text-2`。
- **光学对齐**：图标视觉中心比几何中心高 1px；与文字并排用 `translateY(0.5px)`，不要用 `align-items: baseline`。
- **填色图标只用于"状态"**（成功/警告/错误），其余全部线性；禁止双色图标。
- **命中区**：icon-only 按钮的点击区 ≥32×32（视觉图标可 16–20），必须带 `aria-label`。
- 新增图标必须落在 24×24 视框内、`stroke-linecap: round`、`stroke-linejoin: round`，保持与现有图标同一视觉重量。

## 11. 「反 AI 感」的 8 条硬规则

> 判定标准：把截图给一个没听过这个产品的人看，他能否说出"这是某个具体产品"而不是"这是 AI 生成的页面"。

1. **一屏只有一个视觉焦点。** 只有 1 处 glow、1 个高饱和块、1 个最大字号。第二个焦点必须被降级为 `--text-3`。
2. **渐变只允许两种**：同色相明度变化（`#c9f36d → #ddff94`）、颜色到透明（`accent-soft → transparent`）。**禁止跨色相渐变**（violet→blue、purple→pink、rainbow border）。
3. **玻璃只在浮层。** 卡片/列表/表格零 `backdrop-filter`；每个玻璃必须有实色回退；同屏 ≤1 层（scrim 除外）。
4. **文字三重底线不可破**：≥10.5px、≥4.5:1、正文行高 ≥1.6（中文）。任何"为了高级"而调灰的字，都是 bug。
5. **圆角只有 5 档且必须同心。** 内圆角 = 外 − padding；禁止"内外同半径"；禁止硬编码 7/8/11 这类游离值。
6. **阴影不代表层级。** 卡片零阴影，层级靠 ΔL\*≈3 的 surface + 三档描边；阴影只用于浮层"分离"。
7. **动效 ≤280ms、只动 4 种属性**（transform / opacity / color / box-shadow）；循环动画只允许 skeleton / spinner / 进行中状态点三种。
8. **装饰预算制**：wash ≤2、噪点 ≤1、网格 ≤1、glow ≤1、玻璃 ≤2。**超出预算的设计不是更精致，是更廉价。**

## 12. 主题切换（dark / light）时保持品牌感

### 12.1 核心原则：结构对称，承担者不同

| 维度            | Dark                          | Light                               | 说明                                                                               |
| --------------- | ----------------------------- | ----------------------------------- | ---------------------------------------------------------------------------------- |
| 层级手段        | **亮度阶梯**（ΔL\*≈3）        | **阴影 + 描边**                     | 实测浅色 surface 之间只有 1.03–1.12:1，几乎不可见；把层级压给填充色必失败 `[实测]` |
| 页面底          | `#080b09`（L\*2.81）          | `#f3f0e7`（暖纸，不是纯白）         | 品牌锚点：带绿调的近黑 / 带米调的暖白                                              |
| 卡片            | `#0e1411` + 1px 描边 + 顶高光 | `#fffdf6` + 1px 描边 + 暖阴影       |                                                                                    |
| 阴影            | `rgba(0,0,0,.55–.70)`         | `rgba(53,48,37,.14)`                | 浅色阴影必须**带暖调**，纯黑阴影会显脏                                             |
| 玻璃            | `blur + 72% 底`               | `blur + ≥90% 底` 或干脆实色         | 浅色玻璃几乎无效且发灰                                                             |
| accent          | `#c9f36d`（15.56:1）          | `#4f6b12`（**5.35:1**）             | 亮色主题不能用亮青柠，必须压暗                                                     |
| accent 上的文字 | `#101607`（14.50:1）          | `#f8ffe9`（5.94:1）                 | 反相                                                                               |
| 焦点环          | `--accent` 2px                | `--accent` 2px（对比 5.35:1，可见） | 同一 token，不同值                                                                 |

### 12.2 亮色主题的实测校正（当前代码的缺陷）

| Token                | 现状      | 实测对比度 | 问题       | 建议值    | 新对比度   |
| -------------------- | --------- | ---------- | ---------- | --------- | ---------- |
| `--muted`            | `#6c786d` | **4.05:1** | 低于 AA    | `#55625a` | **5.62:1** |
| `--faint`            | `#8c978d` | ≈2.7:1     | 远低于 AA  | `#5f6b61` | **4.90:1** |
| `--accent`（文字用） | `#5c7d16` | **4.19:1** | 低于 AA    | `#4f6b12` | **5.35:1** |
| `--text-soft`        | `#3f4c42` | 7.93:1     | 可         | 保留      | —          |
| `--text`             | `#182019` | 14.63:1    | 可（略高） | `#1f2a23` | ≈13.04:1   |

> 这是本报告发现的最实际的可及性问题：**亮色主题下的小字元数据当前不达 AA**。

### 12.3 品牌感在切换时必须保留的 6 个锚点

1. **衬线标题**（不改字体、不改字重）。
2. **等宽 eyebrow + 0.14em 字距 + 全大写**（这是"编辑感"的签名）。
3. **22 / 32 大圆角**（明暗都不改）。
4. **网格 + 2.5% 噪点**（浅色下噪点降到 0.015，避免脏）。
5. **accent 的 hue 不漂移**：`#c9f36d` 与 `#4f6b12` 都在同一绿黄色相带（LCH h ≈ 125–130），换的是 L 与 C，不是 h。参考 Linear 用 LCH 保证换主题后"亮度一致、色相不漂" `[A]`。
6. **图标线性权重**：明暗都 1.5px（深色下不要加粗到 1.75）。

### 12.4 切换实现约束

```css
:root {
    color-scheme: dark;
}
:root[data-theme="light"] {
    color-scheme: light;
}

/* 切换动画只作用于颜色，且只挂在容器上（不要 * 全局） */
body,
.surface,
.card,
.dialog__panel {
    transition:
        background-color 180ms var(--ease-standard),
        border-color 180ms var(--ease-standard),
        color 180ms var(--ease-standard);
}
```

- **切换主题不允许改变任何尺寸**（padding / radius / font-size / 行高）。只改颜色与阴影。
- 首帧闪烁：在 `<html>` 上内联 `data-theme`，CSS 里不要用 JS 后置切换。
- 图片/插画需准备两套透明度（深色下的线稿在浅色下会消失）。

## 附录 A：数值计算方法（可复现）

```js
// 相对亮度（WCAG 2.2 / sRGB）
const srgb = (v) => (v <= 0.04045 ? v / 12.92 : Math.pow((v + 0.055) / 1.055, 2.4));
const L = (hex) => {
    const [r, g, b] = hex
        .replace("#", "")
        .match(/../g)
        .map((x) => srgb(parseInt(x, 16) / 255));
    return 0.2126 * r + 0.7152 * g + 0.0722 * b;
};
const contrast = (a, b) => {
    const [hi, lo] = [L(a), L(b)].sort((x, y) => y - x);
    return (hi + 0.05) / (lo + 0.05);
};
// CIELAB L*（用于 surface 阶梯均匀性）
const Lstar = (hex) => {
    const Y = L(hex);
    const f = (t) => (t > 0.008856 ? Math.cbrt(t) : 7.787 * t + 16 / 116);
    return 116 * f(Y) - 16;
};
```
